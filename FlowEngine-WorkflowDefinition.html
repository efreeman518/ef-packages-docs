FlowEngine — Workflow Definition Schema

Complete class signatures for WorkflowDefinition, NodeDefinition, EdgeDefinition, and all 19 node config types.

This document describes the static blueprint format — the JSON (or C#) definition
that describes a workflow's nodes, edges, and configuration. This is distinct
from ExecutionInstance, which represents runtime state. A definition is created
once (or infrequently), versioned, and executed many times.

1. WorkflowDefinition

csharp/// <summary>
/// The static, versioned blueprint for a workflow.
/// Stored in the workflow registry (database, file system, or API).
/// Serializes cleanly to/from JSON. Immutable once published —
/// changes produce a new version.
/// </summary>
public sealed class WorkflowDefinition
{
    // ── Identity ──────────────────────────────────────────────────────────────

    /// <summary>
    /// Stable identifier across versions. URL-safe string.
    /// Examples: "order-fulfillment", "loan-origination", "employee-onboarding"
    /// </summary>
    public string Id      { get; init; }

    /// <summary>
    /// Semantic version (major.minor.patch). A new version is required for
    /// any change to node IDs, edge structure, or config that would alter
    /// the behavior of in-flight instances. In-flight instances always
    /// execute against the version they were started on.
    /// </summary>
    public string Version { get; init; }

    public string  Label       { get; init; }
    public string? Description { get; init; }

    /// <summary>
    /// Plain-language statement of what this workflow does and why.
    /// Written by the workflow builder agent during design conversations.
    /// Not used by the engine — exists for human and agent readability,
    /// future modification discussions, and workflow documentation.
    /// Example: "Process a loan application from submission through
    /// underwriting to a final decision. Auto-approve low-risk, route
    /// medium-risk to a single underwriter, require credit committee
    /// approval (2-of-3) for high-risk."
    /// </summary>
    public string? Intent { get; init; }

    /// <summary>Draft | Active. Only Active definitions accept new instances. Transitions: Draft ↔ Active.</summary>
    public DefinitionStatus Status { get; init; } = DefinitionStatus.Draft;

    public DateTimeOffset CreatedAt   { get; init; }
    public DateTimeOffset UpdatedAt   { get; init; }
    public string?        CreatedBy   { get; init; }

    // ── Graph ─────────────────────────────────────────────────────────────────

    /// <summary>
    /// ID of the node where all new instances begin.
    /// Must reference a node in the Nodes collection.
    /// </summary>
    public string EntryNodeId { get; init; }

    /// <summary>
    /// All nodes in this workflow, keyed by node ID.
    /// Node IDs must be unique within the definition.
    /// At least one node must have no outgoing edges (terminal output node).
    /// </summary>
    public Dictionary<string, NodeDefinition> Nodes { get; init; } = new();

    // ── Error handling ────────────────────────────────────────────────────────

    /// <summary>
    /// Global error handler — node ID to jump to when a node faults
    /// and has no local onFailure edge. If null, the instance transitions
    /// directly to Faulted.
    /// </summary>
    public string? GlobalOnFailureNodeId { get; init; }

    /// <summary>
    /// Global deadline handler — node ID to execute when the instance-level
    /// Deadline is reached. If null, the instance transitions to TimedOut.
    /// </summary>
    public string? GlobalOnDeadlineNodeId { get; init; }

    // ── Default policies ──────────────────────────────────────────────────────

    /// <summary>
    /// Default retry policy applied to all async nodes unless overridden
    /// in the node's own config. Nodes may set retryPolicy: null to
    /// explicitly disable retries.
    /// </summary>
    public RetryPolicy? DefaultRetryPolicy { get; init; }

    /// <summary>
    /// Default circuit breaker policy applied to all nodes that do not specify
    /// their own CircuitBreakerPolicy. null disables circuit breaking by default.
    /// </summary>
    public CircuitBreakerPolicy? DefaultCircuitBreakerPolicy { get; init; }

    /// <summary>
    /// Default lease duration for distributed claim. Overrides the engine
    /// default (30s) for workflows with predictably long node execution times.
    /// </summary>
    public TimeSpan? DefaultLeaseDuration { get; init; }

    // ── Metadata ──────────────────────────────────────────────────────────────

    /// <summary>
    /// Arbitrary tags inherited by all instances of this workflow at creation.
    /// Instance-specific tags (set at invocation time) are merged over these.
    /// </summary>
    public Dictionary<string, string> DefaultTags { get; init; } = new();

    /// <summary>
    /// When true, the engine runs saga compensation on workflow failure: it walks
    /// ExecutionInstance.History in reverse and executes each node's
    /// CompensationNodeId (if set) before routing to GlobalOnFailureNodeId or
    /// faulting the instance. Default: false — existing workflows are unaffected.
    /// </summary>
    public bool EnableCompensation { get; init; } = false;

    /// <summary>
    /// JSON Schema for the parameters accepted at invocation.
    /// The engine validates invocation params against this schema before
    /// creating the instance. Optional — if null, any params are accepted.
    /// </summary>
    public string? ParamsSchema { get; init; }
}

/// 
/// Lifecycle states for a workflow definition.
///   Draft  — under construction; cannot be started; excluded from GetAsync(id, null) results.
///   Active — published; new instances can be started; GetAsync(id, null) returns latest Active version.
///
/// Transitions: Draft ↔ Active (bidirectional).
/// Active definitions are immutable — transition back to Draft to edit.
/// Only Active definitions can be started via IFlowEngine.StartAsync.
/// StartAsync throws WorkflowNotActiveException for Draft definitions.
/// 
public enum DefinitionStatus { Draft, Active }

2. NodeDefinition

csharp/// <summary>
/// A single node in the workflow graph. The Type field determines which
/// INodeExecutor handles it. Config is the type-specific configuration,
/// validated by the executor at startup (not at execution time).
/// </summary>
public sealed class NodeDefinition
{
    public string  Id    { get; init; }   // unique within the workflow
    public string  Type  { get; init; }   // matches INodeExecutor.NodeType
    public string  Label { get; init; }   // human-readable
    public string? Description { get; init; }

    /// <summary>
    /// Plain-language explanation of what this node does and why it exists
    /// at this point in the workflow. Written by the builder agent.
    /// Not used by the engine. Enables the agent to explain any node back
    /// to a business user in natural language without re-reading the config.
    /// Example: "Calculate a composite risk score from the three bureau pulls.
    /// Score above 750 routes to auto-approval; 600-750 to single underwriter;
    /// below 600 requires full credit committee."
    /// </summary>
    public string? Intent { get; init; }

    /// <summary>
    /// Type-specific configuration. Deserialized by the node executor
    /// into its strongly-typed config class (e.g. FilterNodeConfig,
    /// IntegrationNodeConfig). Validated at workflow registration time.
    /// </summary>
    public JsonElement Config { get; init; }

    /// <summary>
    /// Outgoing edges from this node. Evaluated in order — first matching
    /// edge wins. An edge with no Condition matches any outcome (catch-all).
    /// </summary>
    public List<EdgeDefinition> Edges { get; init; } = new();

    /// <summary>
    /// If set, the node's output is written to this context key.
    /// Equivalent to Config-level storeAs but accessible from the
    /// engine without deserializing Config.
    /// </summary>
    public string? StoreAs { get; init; }

    /// <summary>
    /// Optional JSON Schema string (draft-07 subset) validated against the
    /// node's output BEFORE it is written to context via StoreAs.
    /// Only evaluated when StoreAs is also set and the output is a
    /// JsonContextValue. Validation failure → DecisionOutcome.Error;
    /// the invalid value is NOT stored.
    ///
    /// Supported keywords: type, required, properties (with type, enum,
    /// minimum, maximum).
    ///
    /// For agent nodes: AgentNodeConfig.OutputSchema guides the LLM
    /// toward structured output (model-side); this property enforces it
    /// engine-side. Set both to the same schema string when you want
    /// both layers of enforcement.
    ///
    /// Error code on failure: OUTPUT_SCHEMA_VALIDATION_FAILED
    /// </summary>
    public string? OutputSchema { get; init; }

    /// <summary>
    /// Optional map of context keys that must be present in $.context.*
    /// before this node executes. Key = bare context key name (same
    /// convention as StoreAs — no $.context. prefix). Value = optional
    /// JSON Schema string; null means presence-only check.
    ///
    /// Validation runs before the executor is called. Failure →
    /// DecisionOutcome.Error without invoking the executor.
    ///
    /// Error code on failure: CONTEXT_REQUIREMENTS_FAILED
    /// </summary>
    public Dictionary<string, string?>? ContextRequirements { get; init; }

    /// <summary>
    /// Node-level retry policy. Overrides the workflow's DefaultRetryPolicy.
    /// Set to an explicit RetryPolicy with MaxAttempts=0 to disable retries
    /// for this node even if the workflow default enables them.
    /// </summary>
    public RetryPolicy? RetryPolicy { get; init; }

    /// <summary>
    /// Per-node circuit breaker policy. Overrides WorkflowDefinition.DefaultCircuitBreakerPolicy
    /// when set. null falls back to the workflow default; if that is also null, no circuit
    /// breaker is applied to this node.
    /// </summary>
    public CircuitBreakerPolicy? CircuitBreakerPolicy { get; init; }

    /// <summary>
    /// ID of the compensation node to execute during saga rollback.
    /// Only evaluated when WorkflowDefinition.EnableCompensation is true and this node
    /// was successfully executed before the failure. null means no compensation is needed
    /// for this step (idempotent or read-only operations).
    /// </summary>
    public string? CompensationNodeId { get; init; }

    /// <summary>
    /// Maximum times this node may be visited in a single instance execution.
    /// Prevents infinite cycles. Default: 100.
    /// When exceeded, the instance transitions to CycleDetected.
    /// </summary>
    public int MaxVisits { get; init; } = 100;

    /// <summary>
    /// Optional timeout for this specific node's execution.
    /// If the node executor does not complete within this duration,
    /// the engine cancels it and evaluates the Error edge.
    /// Null = no per-node timeout (workflow deadline still applies).
    /// </summary>
    public TimeSpan? ExecutionTimeout { get; init; }
}

3. EdgeDefinition

Available DecisionOutcome values for On: Match · NoMatch · Unknown · Error · Default · CircuitOpen (returned by the engine when a circuit breaker is tripped — not a workflow status; routes to an alternate node or auto-suspends until the circuit cools down).

csharp/// <summary>
/// A directed edge from one node to another.
/// Edges are evaluated in the order they appear in the Edges list.
/// The first edge whose Condition matches the node's DecisionOutcome
/// (and optional predicate) is taken.
/// </summary>
public sealed class EdgeDefinition
{
    /// <summary>
    /// Human-readable label for the edge. Used in the audit history
    /// (NodeExecutionRecord.BranchTaken) and workflow visualisations.
    /// Examples: "Approved", "Insufficient stock", "Timeout"
    /// </summary>
    public string Label { get; init; }

    /// <summary>
    /// ID of the node to execute when this edge is taken.
    /// May reference any node in the workflow including nodes earlier
    /// in the graph (backward edges / cycles).
    /// </summary>
    public string NextNodeId { get; init; }

    /// <summary>
    /// Which DecisionOutcomes this edge matches.
    /// If null or empty, this edge matches ANY outcome (catch-all / default).
    /// Evaluated in list order — first match wins.
    /// </summary>
    public List<DecisionOutcome>? On { get; init; }

    /// <summary>
    /// Optional additional predicate evaluated AFTER the outcome matches.
    /// A Roslyn C# boolean expression compiled and cached at runtime.
    ///
    /// Four globals are in scope — all IReadOnlyDictionary<string, object?>:
    ///   Context  — mutable workflow context ($.context.*)
    ///   Entity   — primary entity fields ($.entity.*)
    ///   Params   — invocation parameters ($.params.*)
    ///   Engine   — runtime metadata: instanceId, workflowId, currentNodeId,
    ///              status (string), visits (Dictionary<string, int>), totalVisits
    ///
    /// Values are unwrapped CLR objects: JSON strings → string, booleans → bool,
    /// JSON numbers → boxed numeric, objects → JsonElement.
    ///
    /// Examples:
    ///   "Context["customerTier"]?.ToString() == "VIP""
    ///   "(decimal)Context["riskScore"] > 80"
    ///   "((Dictionary<string,int>)Engine["visits"]).GetValueOrDefault("n-review") >= 3"
    ///   "Entity["Amount"] != null"
    ///
    /// Allows multiple edges with the same outcome to branch on context data
    /// or engine metadata, enabling decision-tree semantics without a
    /// dedicated decision node.
    /// </summary>
    public string? When { get; init; }
}

4. Node Config types — one per node executor

Each node type defines its own config class. The engine deserializes
NodeDefinition.Config (a JsonElement) into the appropriate type
when the executor runs. Config is validated at workflow registration time,
not at execution time, so misconfigured workflows fail immediately on deploy.

FilterNodeConfig

csharppublic sealed class FilterNodeConfig
{
    /// <summary>
    /// JSONPath to the value in context to filter against.
    /// Defaults to "$.entity" (filter the primary entity).
    ///
    /// Supports all four namespaces:
    ///   "$.entity"                    — filter the primary entity
    ///   "$.context.enrichedCustomer"  — filter a stored context object
    ///   "$.engine"                    — filter engine metadata (e.g. visit counts)
    ///
    /// When targeting "$.engine", the FilterSet property paths are resolved
    /// against the engine metadata object, enabling visit-count-based filters:
    ///   { "propertyPath": "visits.n-review", "operation": "ge", "testValue": 3 }
    /// This checks whether n-review has been visited 3 or more times,
    /// equivalent to ctx.GetVisitCount("n-review") >= 3.
    /// </summary>
    public string Target { get; init; } = "$.entity";

    /// <summary>The FilterSet to evaluate.</summary>
    public FilterSet FilterSet { get; init; }
}

Outcomes: Match, NoMatch, Unknown (null target path), Error

DecisionNodeConfig

csharppublic sealed class DecisionNodeConfig
{
    /// <summary>
    /// JSONPath expression whose resolved value drives case selection.
    /// Example: "$.context.riskTier", "$.entity.Status"
    /// </summary>
    public string ValuePath { get; init; }

    // Branching is entirely in EdgeDefinition.When — no cases here.
    // The decision node simply resolves the value and emits Match.
    // Edges use When predicates to branch on the resolved value.
    // This keeps DecisionNode trivially simple and fully general.
}

Outcomes: Match (always — branching done by edge When predicates), Unknown (path not found), Error

StoreNodeConfig

csharppublic sealed class StoreNodeConfig
{
    /// <summary>
    /// Key to write in $.context. Written as a JsonContextValue.
    /// </summary>
    public string Key { get; init; }

    /// <summary>
    /// JSONPath expression or literal value to write.
    /// If the string starts with "$." it is treated as a JSONPath
    /// and resolved against the current context.
    /// Otherwise it is treated as a literal string value.
    /// For computed values use ComputeNodeConfig instead.
    /// </summary>
    public string Value { get; init; }
}

Outcomes: Match (always), Error

ComputeNodeConfig

csharppublic sealed class ComputeNodeConfig
{
    /// <summary>
    /// A C# expression string evaluated by the Roslyn expression evaluator.
    /// Two variables are in scope:
    ///
    ///   Context  — IReadOnlyDictionary&lt;string, object&gt; of $.context values
    ///   Engine   — IReadOnlyDictionary&lt;string, object&gt; of $.engine metadata
    ///              Keys: "instanceId", "workflowId", "currentNodeId", "status",
    ///                    "createdAt", "correlationId", "parentInstanceId",
    ///                    "visits" (Dictionary&lt;string,int&gt; keyed by nodeId)
    ///              To get total visits: ((Dictionary&lt;string,int&gt;)Engine["visits"]).Values.Sum()
    ///              (Canonical path: $.engine.visits._total — same value)
    ///
    /// Examples:
    ///   "Context[\"subtotal\"] * 1.08"
    ///   "((DateTime)Context[\"dueDate\"] - DateTime.UtcNow).TotalDays"
    ///   "((IEnumerable&lt;decimal&gt;)Context[\"lineAmounts\"]).Sum()"
    ///   "(int)Engine[\"visits\"][\"n-review\"]"                  ← visit count
    ///   "((Dictionary&lt;string,int&gt;)Engine[\"visits\"])[\"n-review\"] >= 3"
    ///   "(Context.ContainsKey(\"reworkCount\") ? (int)Context[\"reworkCount\"] : 0) + 1"
    /// </summary>
    public string Expression { get; init; }
}

Outcomes: Match (expression produced a value), Unknown (expression returned null), Error

TransformNodeConfig

csharppublic sealed class TransformNodeConfig
{
    /// <summary>
    /// Mapping from output key → JSONPath source expression.
    /// Each entry reads a value from the context and writes it under
    /// a new key, producing a reshaped object stored under StoreAs.
    ///
    /// Example:
    /// {
    ///   "customerId":  "$.context.apiResponse.data.id",
    ///   "totalSpend":  "$.context.apiResponse.data.lifetimeValue",
    ///   "tier":        "$.context.apiResponse.data.segment"
    /// }
    /// </summary>
    public Dictionary<string, string> Mapping { get; init; } = new();
}

Outcomes: Match, Unknown (any source path missing), Error

IntegrationNodeConfig

csharp/// <summary>
/// Typed external API call. References a named IRequestResponseClient registered
/// in the IClientRegistry. IntegrationDefinition provides optional schema
/// validation and named field mapping — but the client owns all connection
/// config, auth, and retry policy.
/// </summary>
public sealed class IntegrationNodeConfig
{
    /// <summary>
    /// Name of a registered IRequestResponseClient in the IClientRegistry.
    /// Must be registered before workflow execution starts.
    /// </summary>
    public string ClientRef   { get; init; }

    /// <summary>
    /// Optional. Name of an IntegrationDefinition that provides request/response
    /// schema validation and named field vocabulary. If omitted, the request
    /// mapping is passed directly to the client with no schema validation.
    /// </summary>
    public string? Integration { get; init; }

    /// <summary>
    /// Maps context values → client request fields.
    /// Key = request field name. Value = JSONPath or literal.
    /// </summary>
    public Dictionary<string, string> Request { get; init; } = new();

    /// <summary>
    /// Maps response fields → context keys (JSONPath into response body).
    /// If null, entire response body stored under StoreAs.
    /// </summary>
    public Dictionary<string, string>? ResponseMapping { get; init; }

    /// <summary>
    /// C# expression producing an idempotency key. Required for any
    /// write operation (POST/PUT/DELETE) to prevent duplicate side effects on retry.
    /// Example: "$.entity.OrderId + '-payment'"
    /// </summary>
    public string? IdempotencyKey { get; init; }
}

Outcomes: mapped from HTTP status via IntegrationDefinition.Outcomes if defined,
otherwise Match (2xx), NoMatch (404), Error (other 4xx/5xx/timeout).

FetchNodeConfig (low-level HTTP — use IntegrationNode when possible)

csharppublic sealed class FetchNodeConfig
{
    /// <summary>
    /// Optional. Name of a registered IRequestResponseClient to use for this call.

    /// </summary>
    public string  Url     { get; init; }

    /// <summary>
    /// Request body template (for POST/PUT/PATCH).
    /// JSON string with {{$.context.x}} interpolation.
    /// </summary>
    public string? Body    { get; init; }

    public Dictionary<string, string>? Headers      { get; init; }
    public string?                     CredentialRef { get; init; }
    public int                         TimeoutMs     { get; init; } = 10_000;
}

Outcomes: Match (2xx), NoMatch (404), Error (other 4xx/5xx/timeout)

LoopNodeConfig

csharppublic sealed class LoopNodeConfig
{
    /// <summary>
    /// JSONPath to the collection to iterate over.
    /// Example: "$.entity.LineItems", "$.context.searchResults"
    /// </summary>
    public string Over { get; init; }

    /// <summary>
    /// Context key under which the current item is available to
    /// the sub-workflow. Defaults to "currentItem".
    /// </summary>
    public string ItemAs  { get; init; } = "currentItem";

    /// <summary>Context key for the current 0-based index.</summary>
    public string IndexAs { get; init; } = "currentIndex";

    /// <summary>
    /// ID of the workflow to execute for each item.
    /// May be the same workflow (recursive) or a different named workflow.
    /// </summary>
    public string SubWorkflowId { get; init; }

    /// <summary>
    /// Whether to run iterations sequentially or in parallel.
    /// Sequential is safer for ordered operations (e.g. warehouse picks).
    /// Parallel is faster for independent operations (e.g. enrichment calls).
    /// </summary>
    public LoopMode Mode { get; init; } = LoopMode.Sequential;

    /// <summary>For Parallel mode: max concurrent child instances.</summary>
    public int MaxConcurrency { get; init; } = 10;

    /// <summary>
    /// How to aggregate child outputs back into the parent context.
    /// Key = parent context key. Value = aggregation strategy.
    /// </summary>
    public Dictionary<string, AggregationStrategy>? Aggregate { get; init; }

    /// <summary>
    /// What to do if a child instance faults.
    /// ContinueOnError: log and continue remaining iterations.
    /// StopOnError: abort loop, take Error edge on parent.
    /// </summary>
    public LoopErrorBehavior ErrorBehavior { get; init; } = LoopErrorBehavior.StopOnError;
}

public enum LoopMode          { Sequential, Parallel }
public enum LoopErrorBehavior { StopOnError, ContinueOnError }

public sealed class AggregationStrategy
{
    /// <summary>
    /// collect   — build an array of all child outputs
    /// sum       — numeric sum of a named field: "sum:$.output.amount"
    /// count     — count of completed/matched children
    /// first     — first non-null child output
    /// </summary>
    public string Strategy { get; init; }
    public string? SourcePath { get; init; }  // JSONPath into child output
}

Outcomes: Match (all iterations complete per ErrorBehavior), Error

WorkflowNodeConfig (invoke a sub-workflow — local or remote)

csharppublic sealed class WorkflowNodeConfig
{
    /// <summary>
    /// Optional. Name of a registered IFlowEngineClient for cross-engine invocation.
    /// When null: sub-workflow runs in the same engine (local, in-process).
    /// When set: sub-workflow is dispatched to the named remote FlowEngine instance.
    /// </summary>
    public string? ClientRef   { get; init; }

    /// <summary>ID of the workflow to invoke.</summary>
    public string WorkflowId   { get; init; }

    /// <summary>Version constraint. Null = latest active.</summary>
    public string? Version     { get; init; }

    /// <summary>
    /// Values to pass as the sub-workflow's $.params.
    /// Key = param name, Value = JSONPath expression or literal.
    /// </summary>
    public Dictionary<string, string>? Params { get; init; }

    /// <summary>
    /// JSONPath to the value passed as the sub-workflow's $.entity.
    /// Defaults to "$.entity" (same primary entity).
    /// </summary>
    public string EntityPath   { get; init; } = "$.entity";

    /// <summary>
    /// false (default): parent suspends until sub-workflow reaches terminal state.
    /// true: parent advances immediately; sub-workflow runs independently.
    /// When true, storeAs will always be null (parent never sees the output).
    /// </summary>
    public bool FireAndForget  { get; init; } = false;
}

Outcomes:
- Local (clientRef null): Match (child Completed), NoMatch (child Completed, no output), Error (child Faulted/TimedOut/Cancelled)
- Remote (clientRef set): same outcomes, determined by RemoteInstanceRef.Outcome

ParallelNodeConfig

csharppublic sealed class ParallelNodeConfig
{
    /// <summary>Sub-workflow IDs to execute concurrently.</summary>
    public List<string> Branches { get; init; } = new();

    /// <summary>
    /// How many branches must complete before the parent resumes.
    ///   All          — every branch must complete (default)
    ///   FirstOf      — resume when any one branch completes
    ///   Threshold(N) — resume when N branches complete
    /// </summary>
    public ParallelJoinStrategy JoinStrategy { get; init; } = ParallelJoinStrategy.All;
    public int JoinThreshold { get; init; } = 0; // used when JoinStrategy = Threshold

    /// <summary>
    /// What to do when a branch faults before the join condition is met.
    ///   StopAll      — cancel remaining branches, take Error edge
    ///   ContinueWithPartial — count faulted branches toward threshold if
    ///                          that still allows the join condition to be met
    /// </summary>
    public ParallelErrorBehavior ErrorBehavior { get; init; } = ParallelErrorBehavior.StopAll;

    /// <summary>
    /// Values to pass as each branch sub-workflow's $.params.
    /// Keyed by branch workflow ID.
    ///
    /// KEY COLLISION NOTE: BranchParams is keyed by workflow ID.
    /// If two or more entries in Branches reference the SAME workflow ID
    /// (e.g. running the same sub-workflow with different entities),
    /// only the LAST entry in BranchParams for that workflow ID is used —
    /// the earlier entries are silently overwritten.
    ///
    /// Workaround: wrap the repeated sub-workflow in a distinct
    /// named wrapper workflow per branch, or pass distinguishing
    /// params via the branch entity rather than BranchParams.
    /// </summary>
    public Dictionary<string, Dictionary<string, string>>? BranchParams { get; init; }

    /// <summary>
    /// How to aggregate branch outputs into the parent context.
    /// Each completed branch's Output is available as a child instance.
    /// If null, branch outputs are accessible via GetChildrenAsync but
    /// are NOT automatically merged into the parent's $.context.
    ///
    /// Aggregation strategies per key:
    ///   collect — array of all branch output values for this field
    ///   first   — value from the first branch to complete
    ///   merge   — shallow merge of all branch output objects
    ///
    /// Example: aggregate: { "checkResults": { "strategy": "collect" } }
    /// → $.context.checkResults = [ branch1Output, branch2Output, ... ]
    /// </summary>
    public Dictionary<string, ParallelAggregationSpec>? Aggregate { get; init; }
}

public sealed class ParallelAggregationSpec
{
    /// <summary>"collect" | "first" | "merge"</summary>
    public string Strategy { get; init; } = "collect";
    /// <summary>JSONPath into each branch's output object. Null = entire output.</summary>
    public string? SourcePath { get; init; }
}

public enum ParallelJoinStrategy  { All, FirstOf, Threshold }
public enum ParallelErrorBehavior { StopAll, ContinueWithPartial }

Parallel output aggregation:

Branch outputs land in the parent context only if Aggregate is configured.
Without it, outputs are queryable via IExecutionStateStore.GetChildrenAsync
but are not automatically available as context keys.

json{
  "type": "parallel",
  "storeAs": "checks",
  "config": {
    "branches":      ["credit-check", "fraud-check", "inventory-check"],
    "joinStrategy":  "All",
    "errorBehavior": "StopAll",
    "branchParams": {
      "credit-check":    { "applicantId": "$.entity.ApplicantId" },
      "fraud-check":     { "applicantId": "$.entity.ApplicantId" },
      "inventory-check": { "productId":   "$.entity.ProductId" }
    },
    "aggregate": {
      "checkResults": { "strategy": "collect" }
    }
  }
}

After join, $.context.checks.checkResults is an array of each branch's
output. Use a subsequent compute or filter node to evaluate the combined results.

DbContext thread safety in parallel branches. Each parallel branch spawns an independent ExecutionInstance and runs on its own thread-pool thread. DbContext is not thread-safe — sharing a single instance across branches will throw InvalidOperationException: A second operation was started on this context before a previous operation completed.

Required pattern — use IDbContextFactory<T>:

// ✅ Register the factory (pooled recommended for throughput)
builder.Services.AddPooledDbContextFactory<MyDbContext>(options => ...);

// ✅ Each branch resolves its own DbContext instance via the factory
flowEngineBuilder.AddClient(sp =>
    new EfQueryClient<MyDbContext>(
        clientRef: "my-db",
        factory:   sp.GetRequiredService<IDbContextFactory<MyDbContext>>(),
        ...));

The engine shares a single root IServiceProvider across branches. Clients registered via AddClient that internally call factory.CreateDbContext() are thread-safe because each call produces a new, independent context instance. Clients that hold any shared DbContext — whether registered as singleton or scoped — are not safe for parallel use. The engine does not create a new DI scope per branch, so a scoped DbContext is still shared across all concurrent branches.

Do not inject a DbContext directly (singleton or scoped) into any client that participates in parallel branches. Always use IDbContextFactory<T>.

CheckpointNodeConfig — force mid-chain state persistence

csharp/// <summary>
/// Forces an immediate SaveAsync before the engine advances to the next node.
/// The only node type that triggers a mid-loop save.
///
/// Use before chains of expensive or non-idempotent nodes to bound the
/// re-execution window on crash recovery. Without a checkpoint, a crash
/// anywhere in a long synchronous chain causes the entire chain to re-execute
/// from the last saved CurrentNodeId (typically the entry node).
///
/// The executor returns ForceCheckpoint: true in NodeResult. The engine loop
/// detects this flag and calls SaveWithRetryAsync before advancing.
/// After saving, CurrentNodeId is updated to the next node — so crash recovery
/// resumes from AFTER the checkpoint, not before it.
///
/// CheckpointNodeConfig has no configuration fields.
/// </summary>
public sealed class CheckpointNodeConfig { }

json{
  "id":    "n-checkpoint-1",
  "type":  "checkpoint",
  "label": "Persist before payment chain",
  "intent": "Force a state store write here. The credit score and risk tier computation above is expensive — checkpoint ensures crash recovery resumes from here rather than re-running those compute nodes.",
  "edges": [
    { "on": ["Match"], "nextNodeId": "n-charge-card" }
  ]
}

When to use:
- Before a chain of write operations (charge card → allocate stock → create shipment) where re-execution from the start would cause duplicate side effects even with idempotency keys
- After a long expensive compute chain you don't want to repeat on crash recovery
- Before a loop or parallel node that spawns many child instances

When NOT to use:
- Between every node — the performance cost of a state store round-trip applies; use sparingly
- As a substitute for idempotency keys on write operations — always implement idempotency on write nodes regardless of whether a checkpoint precedes them

Outcomes: Match (always). No Error outcome — if SaveAsync fails after retry the engine faults the instance anyway.

7. Workflow versioning and migration guidance

Core invariant

A WorkflowDefinition is immutable once published (status = Active).
Running instances pin to the exact version at creation via WorkflowVersion
on ExecutionInstance. Changing a published definition requires a new version.

Versioning strategy

loan-origination @ 1.0.0  ← Active — new instances start here
loan-origination @ 1.1.0  ← Active — new instances start here (latest wins)
loan-origination @ 0.9.0  ← Draft  — transitioned back to prevent new instances; in-flight continue

To release a change:
1. SaveAsync a new definition with incremented version and status: Active
2. Optionally transition the old version back to Draft (prevents new instances, in-flight continue)
3. In-flight instances on the old version will complete normally — they are pinned

Breaking vs non-breaking changes

Change Typical impact Notes
Add a new node with a new ID Usually compatible In-flight instances never reach the new node
Change an edge condition Usually compatible New version only — in-flight use old edges
Change node intent or label Usually compatible Informational only
Change storeAs on a node Needs review Downstream nodes reading the old key will get null
Remove or rename a node ID Likely breaking In-flight instances at CurrentNodeId = old-id will fault on next sweep
Change entryNodeId Likely breaking for in-flight instances New instances unaffected; in-flight may already be past entry
Change correlationKeyPath on wait node Likely breaking Suspended instances have the old correlation key stored in WaitDescriptor.CorrelationKey

Handling in-flight instances during migration

Pattern 1 — Drain and switch:
Transition the old version back to Draft. Wait until all in-flight instances reach
a terminal state (query status = Suspended count → 0). Then no active
instances run the old version.

Pattern 2 — Parallel versions:
Run both versions simultaneously. Old instances complete on v1.x.
New instances start on v2.0. Use Tags to distinguish: { "schemaVersion": "2" }.

Pattern 3 — Forced migration (use MigrateInstanceAsync):
If a node was renamed and in-flight instances are stuck at CurrentNodeId = old-id,
they will fault on the next sweep cycle with NODE_NOT_FOUND.
Use the built-in migration API:

await engine.MigrateInstanceAsync(
    instanceId,
    targetVersion: "2.0.0",
    nodeIdMap: new Dictionary<string, string>
    {
        ["n-old-approval"] = "n-manager-approval"   // renamed node
    },
    ct);
// Instance is now pinned to v2.0.0 — resume normally
await engine.ResumeByInstanceIdAsync(instanceId, ct: ct);

MigrateInstanceAsync validates the remap, updates WorkflowVersion and CurrentNodeId, appends a migration history record, and saves state — without replaying history. It throws if the instance is in a terminal state or if the remapped node does not exist in the target definition. To cancel an instance that cannot be safely migrated, use engine.CancelAsync(instanceId, ct).

Testing version compatibility

Before deploying a new version:
1. Register the new definition in a test environment with status: Draft
2. Start representative instances against it
3. Walk instances through all node types including suspend/resume paths
4. Confirm all $.engine.visits.* and when predicates resolve correctly
5. Promote to Active only after all paths are validated

The GlobalOnFailureNodeId safety net

All versions should define GlobalOnFailureNodeId pointing to a graceful
failure output node. This ensures instances that encounter an unexpected
node type or missing edge are routed to a known terminal state rather than
faulting silently.
