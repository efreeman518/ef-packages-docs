Client Throttle Policies

All IFlowClient implementations can declare two throttle policies. When either is set, ClientRegistry automatically wraps the client — no executor changes needed. Both policies apply cluster-wide when a distributed throttle provider is registered (default: in-process only).

ConcurrencyLimit — max simultaneous in-flight calls

Override ConcurrencyLimit to cap how many calls to this client can be in-flight at once. The registry wraps the client; each caller acquires a slot before the call and releases it on completion or exception.

ScenarioRecommended limit
Client wraps a non-thread-safe resource (e.g. raw DbContext)1
External API with a documented concurrent-call quotaN matching the quota
Database connection pool protectionFraction of pool size (e.g. pool/2)
Thread-safe client, no external constraintnull (default — no limit)

RateLimit — max calls per time window

Override RateLimit to cap how many calls can be made within a sliding time window. Uses a RateLimitPolicy record:

PropertyTypeDescription
LimitintMaximum calls within the window
WindowTimeSpanSliding window duration (e.g. TimeSpan.FromMinutes(1))
OverflowThrottleOverflowPolicyBlock (default) — waits until a slot is available; Reject — throws ThrottleCapacityExceededException immediately

Usage

csharppublic class MyApiClient : IRequestResponseClient
{
    public string             ClientRef        => "rate-limited-api";
    public int?               ConcurrencyLimit => 5;   // max 5 simultaneous calls
    public RateLimitPolicy?   RateLimit        => new(Limit: 100, Window: TimeSpan.FromMinutes(1));

    public Task ValidateAsync(CancellationToken ct = default) => Task.CompletedTask;

    public async Task<ClientResponse> ExecuteAsync(ClientRequest request, CancellationToken ct)
    {
        // throttle already applied by the registry wrapper before this is called
        var response = await _http.PostAsJsonAsync("/api/call", request.Body, ct);
        return new ClientResponse { StatusCode = (int)response.StatusCode, ... };
    }
}

Distributed Throttle Providers

By default both policies are enforced in-process (InMemoryDistributedThrottleProvider). In a multi-node deployment each replica enforces limits independently — total cluster concurrency is limit × node-count. Replace the default with a distributed provider to share limits across all replicas:

ProviderPackageUse when
InMemory (default)Built into EF.FlowEngineSingle process, dev/test, or when cluster-wide throttling is not required
RedisEF.FlowEngine.Throttles.RedisMulti-node — fast atomic Lua scripts; sliding-window rate + INCR concurrency counter
SQLEF.FlowEngine.Throttles.SqlMulti-node without Redis — EF Core optimistic-concurrency; fixed-window rate
csharp// Redis — requires IConnectionMultiplexer in DI
builder.UseThrottleProviderRedis();

// SQL — TContext must implement IFlowEngineThrottleDbContext
// and call mb.ApplyFlowEngineThrottle() in OnModelCreating
builder.UseThrottleProviderSql<AppDbContext>();
Interaction with MaxConcurrency on loop/parallel nodes. The loop node's maxConcurrency controls how many child workflows are spawned simultaneously. ConcurrencyLimit on a client controls how many of those children can call that specific client at the same time. Both limits apply independently — you can have 20 parallel branches with a client limit of 3, meaning 17 branches wait for a slot while 3 are calling the client.

HTTP Client

Package: EF.FlowEngine.Clients.Http

ResilientHttpFlowClient wraps an HttpClient with the Microsoft.Extensions.Http.Resilience standard pipeline (retry + circuit breaker + hedging). Implements IFlowClient / IRequestResponseClient.

Registration

csharpbuilder.Services.AddFlowEngine()
    .AddResilientHttpClient(
        clientRef:   "payment-api",
        baseAddress: new Uri("https://payments.internal/"),
        configure:   pipeline =>
        {
            // Customize the resilience pipeline (optional)
            pipeline.AddRetry(new HttpRetryStrategyOptions
            {
                MaxRetryAttempts = 3,
                Delay = TimeSpan.FromMilliseconds(500),
                BackoffType = DelayBackoffType.Exponential
            });
        });

Uses the same clientRef naming convention as all other FlowEngine clients — reference it in workflow nodes as "clientRef": "payment-api".

For a plain client without the resilience pipeline (e.g. the caller owns retries), register DirectHttpFlowClient instead:

csharpbuilder.Services.AddFlowEngine()
    .AddDirectHttpClient(clientRef: "payment-api");   // optional namedClient parameter

Default resilience pipeline

When no configure delegate is provided, the standard Microsoft.Extensions.Http.Resilience pipeline applies:

  • Retry: up to 3 attempts, exponential backoff, jitter
  • Circuit breaker: opens after 10 failures in 30 s, stays open for 30 s
  • Timeout: 30 s per attempt
Tip: The HTTP-level resilience pipeline and FlowEngine's workflow-level circuitBreakerPolicy / retryPolicy are independent layers. The HTTP pipeline guards individual HTTP calls; the workflow policy guards node execution attempts. Both can coexist — size timeouts and thresholds accordingly.

Service Bus Client

Package: EF.FlowEngine.Clients.ServiceBus

ServiceBusMessageClient implements IMessageClient and IFlowClient. Supports FireAndForget and RequestReply delivery modes. RequestReply uses PendingWait (correlation ID on the reply queue) to suspend and resume the workflow instance.

Registration

csharpbuilder.Services.AddFlowEngine()
    // Simple — resolves ServiceBusClient from DI
    .AddServiceBusClient(
        clientRef:        "order-events",
        topicOrQueueName: "orders");

    // Or provide the ServiceBusClient directly
    .AddServiceBusClient(
        clientRef:         "order-events",
        serviceBusClient:  new ServiceBusClient(connectionString),
        topicOrQueueName:  "orders",
        replyQueueName:    "orders-reply");   // required for RequestReply

Workflow usage

json// FireAndForget — publish and move on
{
  "type": "message",
  "config": {
    "clientRef":      "order-events",
    "subject":        "order.completed",
    "body":           { "orderId": "$.entity.OrderId", "total": "$.context.orderTotal" },
    "deliveryMode":   "FireAndForget",
    "idempotencyKey": "$.entity.OrderId + '-complete'"
  }
}

// RequestReply — publish and suspend until reply arrives
{
  "type": "message",
  "config": {
    "clientRef":      "payment-processor",
    "subject":        "payment.requested",
    "body":           { "amount": "$.context.orderTotal", "customerId": "$.entity.CustomerId" },
    "deliveryMode":   "RequestReply",
    "replyEventName": "payment.completed",
    "replyTimeout":   "PT5M",
    "idempotencyKey": "$.entity.OrderId + '-payment'"
  }
}

Message properties

The subject is written as the Service Bus message Subject property. The body object is JSON-serialized as the message body. Use the properties map in the node config to set additional application properties on the Service Bus message.

OpenAI / Azure AI Client

Package: EF.FlowEngine.Clients.OpenAI

OpenAIAgentClient implements IAgentClient backed by Microsoft.Extensions.AI IChatClient. Works with any ME.AI-compatible provider: OpenAI, Azure OpenAI, Microsoft Foundry, Ollama, and more. Emits token usage telemetry via IFlowEngineTelemetry.

Registration

csharp// OpenAI
var openAIClient = new OpenAIClient(builder.Configuration["OpenAI:ApiKey"]!);
builder.Services.AddFlowEngine()
    .AddOpenAIAgentClient(
        clientRef:  "gpt4o",
        chatClient: openAIClient.AsChatClient("gpt-4o"),
        modelName:  "gpt-4o");   // stored in telemetry; not used for routing

// Azure OpenAI
var azureClient = new AzureOpenAIClient(new Uri(endpoint), new DefaultAzureCredential());
builder.Services.AddFlowEngine()
    .AddOpenAIAgentClient(
        clientRef:  "azure-gpt4",
        chatClient: azureClient.AsChatClient("gpt-4o-deployment"),
        modelName:  "gpt-4o");

// Any IChatClient — Ollama, Semantic Kernel, Microsoft Agent Framework, etc.
builder.Services.AddFlowEngine()
    .AddOpenAIAgentClient(
        clientRef:  "local-llm",
        chatClient: new OllamaChatClient(new Uri("http://localhost:11434"), "llama3"),
        modelName:  "llama3");

A no-Azure-SDK variant ships as EF.FlowEngine.Clients.AI (ChatClientAgentClient). Register any DI-resolved IChatClient and bind it to an agent-node clientRef:

csharpbuilder.Services.AddChatClient(/* your IChatClient */);
builder.Services.AddFlowEngine()
    .AddChatClientAgentClient(clientRef: "assistant");

How prompts are built

The executor renders AgentNodeConfig.promptTemplate by resolving {{key}} tokens against the node's input mapping (JSONPath → value), then constructs a UserChatMessage. The IChatClient receives:

  • A UserChatMessage with the rendered prompt text
  • ChatOptions.ResponseFormat = ChatResponseFormat.Json when outputSchema is set
  • A cancellation token governed by AgentNodeConfig.timeoutMs

Token usage

After each call, OpenAIAgentClient reads ChatResponse.Usage and emits input/output/total token counts via IFlowEngineTelemetry. These appear as tags on the flow.agent.completed event. Configure per-model rates in FlowEngineOptions.AgentModelRates to get estimatedCostUsd in telemetry.

ME.AI 10.0 API notes: Uses IChatClient.GetResponseAsync (not the preview-era CompleteAsync). Token counts are typed as long? from ChatResponse.Usage. Model name is passed at construction time rather than read from IChatClient.Metadata (removed in 10.0).

SQL Query Clients

Package: EF.FlowEngine.Clients.Sql

Two implementations of IQueryClient for SQL Server data sources. Both translate a FilterSet into a query against a relational database — one via EF Core (typed, startup-registered), the other via raw ADO.NET (dynamic, UI-configurable).

EfQueryClient<TContext>

Typed EF Core client. Use when you have a DbContext for the target database and want compile-time safety and full EF Core feature support. Must be registered in code at startup — it requires a compile-time generic type parameter.

csharp// Register in Program.cs (Dashboard.UI or production worker)
flowEngineBuilder.AddClient(sp =>
    new EfQueryClient<CrmDbContext>(
        clientRef:   "crm-query",
        factory:     sp.GetRequiredService<IDbContextFactory<CrmDbContext>>(),
        typeMap:     CrmDbContext.EntityTypeMap,    // IReadOnlyDictionary<string, Type>
        setResolver: (db, entity) => entity.ToLowerInvariant() switch {
            "customer" => db.Customers,
            "order"    => db.Orders,
            _          => null
        }));

// EntityTypeMap on the DbContext — maps entityType names to CLR types
public static IReadOnlyDictionary<string, Type> EntityTypeMap =
    new Dictionary<string, Type>(StringComparer.OrdinalIgnoreCase)
    {
        ["Customer"] = typeof(Customer),
        ["Order"]    = typeof(Order),
    };

The client applies FilterBuilder<T>.ProcessFilterSet(query.FilterSet) via reflection using the resolved CLR type, then handles all result modes (Count, Any, First, All, Page).

A dedicated DI extension is also available so you don't have to hand-wire the constructor:

csharpflowEngineBuilder.AddEfQueryClient<CrmDbContext>(
    clientRef:   "crm-query",
    typeMap:     CrmDbContext.EntityTypeMap,
    setResolver: (db, entity) => entity.ToLowerInvariant() switch { "customer" => db.Customers, _ => null });
Parallel branches — why IDbContextFactory<T> is required. DbContext is not thread-safe. When EfQueryClient<TContext> is invoked from parallel workflow branches (each running on its own thread-pool thread), every call internally invokes factory.CreateDbContext(), which produces a fresh, independent context instance. This is safe. If you inject a DbContext directly — whether singleton or scoped — concurrent branches will throw InvalidOperationException: A second operation was started on this context…. The engine does not create a new DI scope per branch, so a scoped DbContext is still shared across all branches. Always register with AddPooledDbContextFactory<T> and resolve IDbContextFactory<T> at client construction.

If you cannot use a factory (e.g. a legacy client wrapping a non-thread-safe resource), set ConcurrencyLimit = 1 on the client — the registry will serialize all calls through a semaphore. This is a safety net, not a substitute for proper thread safety: serialized calls to a shared DbContext still accumulate change-tracker state across callers. Prefer IDbContextFactory<T>. See Client Concurrency Limits.

AdHocSqlQueryClient

Dynamic SQL client for ad-hoc access to any SQL Server table by connection string and an entity-name → schema.Table map. Translates FilterSet predicates to parameterized SQL WHERE clauses at runtime. No EF Core or compile-time types required — results are returned as Dictionary<string, object?> rows.

csharp// Registered in code:
flowEngineBuilder.AddClient(
    new AdHocSqlQueryClient(
        clientRef:     "legacy-query",
        connectionString: config["LegacyDb:ConnectionString"],
        entityTableMap: new Dictionary<string, string> {
            ["Invoice"]  = "dbo.Invoices",
            ["LineItem"] = "dbo.InvoiceLines",
        }));

// Or use the dedicated DI extension:
flowEngineBuilder.AddAdHocSqlQueryClient(
    clientRef:        "legacy-query",
    connectionString: config["LegacyDb:ConnectionString"],
    entityTableMap:   new Dictionary<string, string> { ["Invoice"] = "dbo.Invoices" });

// Or added at runtime via the Dashboard Client Registry page (/clients).
// Persisted to clientconfigs.json and reloaded on restart.

Supported filter operations: eq, neq, gt, lt, gte, lte, contains (LIKE), startswith (LIKE), endswith (LIKE), in, nin (NOT IN), isnull, isnotnull. Case sensitivity is respected via LOWER() wrapping when CaseSensitive: false.

Choose the right client: Prefer EfQueryClient<TContext> for production — it uses EF Core's query pipeline, respects navigation properties, and gives compile-time type safety. Use AdHocSqlQueryClient for dev/prototyping, legacy databases you can't model in EF Core, or UI-added query clients where the developer cannot redeploy.

Custom Client Patterns

All FlowEngine client interfaces are simple to implement. Register via .AddClient(name, instance) or .AddClient<T>() (DI-resolved).

IQueryClient

csharppublic class MyQueryClient : IQueryClient
{
    public string ClientRef => "my-query";

    public Task ValidateAsync(CancellationToken ct = default) => Task.CompletedTask;

    public Type? ResolveEntityType(string entityTypeName) => entityTypeName.ToLower() switch
    {
        "record" => typeof(MyRecord),
        _        => null
    };

    public async Task<QueryResult> QueryAsync(DataSourceQuery query, CancellationToken ct)
    {
        // query.EntityType   — entity name string
        // query.FilterSet    — structured filter predicates
        // query.OrderBy      — sort column + direction
        // query.Skip / Take  — paging
        // query.ResultMode   — Count | Any | First | All | Page

        var results = await MyStore.QueryAsync(query, ct);

        return new QueryResult
        {
            Items      = results.Items,
            TotalCount = results.Total,
            Outcome    = DecisionOutcome.Match
        };
    }
}

IAgentClient

csharppublic class MyCustomAgentClient : IAgentClient
{
    public string ClientRef => "my-agent";

    public Task ValidateAsync(CancellationToken ct = default)
    {
        // Called before the first workflow execution that uses this client
        // Throw to fail fast with a clear message
        return Task.CompletedTask;
    }

    public async Task<AgentResponse> InvokeAsync(AgentRequest request, CancellationToken ct)
    {
        // request.Prompt          — rendered prompt template
        // request.IdempotencyKey  — forwarded from AgentNodeConfig
        // request.OutputSchema    — JSON Schema string (if set)

        var result = await MyAiService.CallAsync(request.Prompt, ct);

        return new AgentResponse
        {
            Output    = JsonSerializer.SerializeToElement(result),
            Succeeded = true,
            Outcome   = DecisionOutcome.Match,
            TokensUsed = result.TotalTokens
        };
    }
}

// Register
builder.Services.AddFlowEngine()
    .AddClient("my-agent", new MyCustomAgentClient());

IMessageClient

csharppublic class MyMessageClient : IMessageClient
{
    public string ClientRef => "my-bus";

    public Task ValidateAsync(CancellationToken ct = default) => Task.CompletedTask;

    public Task SendAsync(MessageRequest request, CancellationToken ct)
    {
        // FireAndForget — publish and return
        return MyBusClient.PublishAsync(request.Subject, request.Body, ct);
    }

    public Task<string> SendAndWaitAsync(MessageRequest request, CancellationToken ct)
    {
        // RequestReply — return a correlation key that identifies the pending reply
        // Engine suspends the instance; harness calls engine.ResumeAsync when reply arrives
        return MyBusClient.PublishWithCorrelationAsync(request.Subject, request.Body, ct);
    }
}

IRequestResponseClient

csharppublic class MyApiClient : IRequestResponseClient
{
    public string ClientRef => "my-api";

    public Task ValidateAsync(CancellationToken ct = default) => Task.CompletedTask;

    public async Task<IntegrationResponse> CallAsync(IntegrationRequest request, CancellationToken ct)
    {
        var httpResponse = await _http.PostAsJsonAsync("/api/call", request.Body, ct);
        return new IntegrationResponse
        {
            StatusCode = (int)httpResponse.StatusCode,
            Body       = await httpResponse.Content.ReadFromJsonAsync<JsonElement>(ct)
        };
    }
}

Agent Governance

Content Filtering

Register a named IContentFilter to run pre/post checks on every agent call that references it by name.

IContentFilter contract

csharppublic interface IContentFilter
{
    string Name { get; }

    // Called before the LLM — receives the rendered prompt
    Task<ContentFilterResult> FilterInputAsync(string prompt, CancellationToken ct = default);

    // Called after the LLM — receives the raw text response
    Task<ContentFilterResult> FilterOutputAsync(string response, CancellationToken ct = default);
}

public sealed class ContentFilterResult
{
    public bool    IsAllowed           { get; init; }
    public string? ReplacementContent  { get; init; }  // stored as output if IsAllowed = false
    public string? Reason              { get; init; }  // recorded in NodeExecutionRecord.Error
}

Example — Azure AI Content Safety

csharppublic class AzureContentSafetyFilter : IContentFilter
{
    private readonly ContentSafetyClient _client;

    public string Name => "azure-content-safety";

    public AzureContentSafetyFilter(ContentSafetyClient client) => _client = client;

    public async Task<ContentFilterResult> FilterInputAsync(string prompt, CancellationToken ct)
    {
        var analysis = await _client.AnalyzeTextAsync(new AnalyzeTextOptions(prompt), ct);
        var blocked  = analysis.Value.CategoriesAnalysis.Any(c => c.Severity >= 4);
        return new ContentFilterResult
        {
            IsAllowed = !blocked,
            Reason    = blocked ? "Prompt flagged by Azure Content Safety" : null
        };
    }

    public async Task<ContentFilterResult> FilterOutputAsync(string response, CancellationToken ct)
    {
        var analysis = await _client.AnalyzeTextAsync(new AnalyzeTextOptions(response), ct);
        var blocked  = analysis.Value.CategoriesAnalysis.Any(c => c.Severity >= 4);
        return new ContentFilterResult
        {
            IsAllowed          = !blocked,
            ReplacementContent = blocked ? "[Content filtered]" : null,
            Reason             = blocked ? "Response flagged by Azure Content Safety" : null
        };
    }
}

// Register
builder.Services.AddSingleton<IContentFilter, AzureContentSafetyFilter>();

Using in a workflow node

json{
  "type": "agent",
  "config": {
    "clientRef":           "gpt4o",
    "promptTemplate":      "Summarise this document: {{$.context.documentText}}",
    "contentFilterPolicy": "azure-content-safety"
  }
}

Filter execution flow

  1. Engine resolves the named IContentFilter from DI by Name
  2. FilterInputAsync(renderedPrompt) — if IsAllowed: false, node short-circuits with DecisionOutcome.Error. ReplacementContent (if set) is stored as the node output.
  3. LLM call proceeds normally
  4. FilterOutputAsync(responseText) — if IsAllowed: false, same short-circuit applies. Blocked response text is not stored.
Registration required: If contentFilterPolicy names a filter that is not registered in DI, the node faults at execution time with a descriptive error. Register all referenced filters before the application starts.

Prompt Versioning

Set AgentNodeConfig.promptVersion to a label string. The value is recorded in NodeExecutionRecord.Metadata["promptVersion"] for every invocation of that node — enabling prompt A/B analysis and rollback tracking without changing the workflow definition ID or version.

json{
  "type": "agent",
  "config": {
    "clientRef":      "gpt4o",
    "promptTemplate": "Classify the risk tier of this loan application: {{$.entity.Summary}}",
    "promptVersion":  "v3.2-risk-classify"
  }
}

Query execution history grouped by promptVersion to compare outcomes, latency, and token usage across prompt iterations:

csharpvar records = instance.History
    .Where(r => r.NodeId == "n-classify-risk" && r.Metadata.ContainsKey("promptVersion"))
    .GroupBy(r => r.Metadata["promptVersion"])
    .Select(g => new
    {
        PromptVersion = g.Key,
        AvgLatencyMs  = g.Average(r => int.Parse(r.Metadata.GetValueOrDefault("latencyMs", "0"))),
        SuccessRate   = g.Count(r => r.Outcome == DecisionOutcome.Match) / (double)g.Count()
    });

Telemetry & Cost Tracking

AgentNodeExecutor emits a flow.agent.completed event via IFlowEngineTelemetry after every agent call. The event carries structured tags for OTel, custom metrics, and cost reporting.

Telemetry tags

TagTypeDescription
nodeIdstringNode ID in the workflow graph
clientRefstringName of the registered IAgentClient
promptHashstringSHA-256 (first 16 chars) of the rendered prompt — for prompt change detection
latencyMslongEnd-to-end call latency in milliseconds
tokensUsedint?Total tokens consumed (input + output)
promptVersionstring?Value of AgentNodeConfig.promptVersion
estimatedCostUsddecimal?Computed from FlowEngineOptions.AgentModelRates × token counts

These same tags are written to NodeResult.Metadata and persisted in NodeExecutionRecord.Metadata — queryable in the history without an OTel collector.

Per-model cost rates

csharpbuilder.Services.AddFlowEngine(options =>
{
    options.AgentModelRates["gpt-4o"] = new ModelCostRate
    {
        InputCostPerToken  = 0.000005m,   // $5.00 / 1M input tokens
        OutputCostPerToken = 0.000015m    // $15.00 / 1M output tokens
    };

    options.AgentModelRates["gpt-4o-mini"] = new ModelCostRate
    {
        InputCostPerToken  = 0.00000015m,
        OutputCostPerToken = 0.00000060m
    };
});

The model name is set at client registration time via modelName parameter on AddOpenAIAgentClient. If a model name has no entry in AgentModelRates, estimatedCostUsd is emitted as null.

Custom IFlowEngineTelemetry

csharppublic class MyTelemetry : IFlowEngineTelemetry
{
    private readonly ILogger<MyTelemetry> _logger;
    private readonly IMeterFactory        _meters;

    public MyTelemetry(ILogger<MyTelemetry> logger, IMeterFactory meters)
    {
        _logger = logger;
        _meters = meters;
    }

    public void RecordEvent(string eventName, IReadOnlyDictionary<string, object?> tags)
    {
        if (eventName == "flow.agent.completed")
        {
            var latency = tags.GetValueOrDefault("latencyMs") as long? ?? 0;
            var cost    = tags.GetValueOrDefault("estimatedCostUsd") as decimal?;
            var model   = tags.GetValueOrDefault("clientRef")?.ToString();

            _logger.LogInformation(
                "Agent {Client} completed in {LatencyMs}ms, est. cost ${Cost:F6}",
                model, latency, cost);
        }
    }
}

// Register
builder.Services.AddFlowEngine()
    .UseTelemetry<MyTelemetry>();
OTel integration: Pipe IFlowEngineTelemetry events into System.Diagnostics.ActivitySource or System.Diagnostics.Metrics.Meter to export to Azure Monitor, Datadog, Jaeger, or any OTel-compatible collector.
