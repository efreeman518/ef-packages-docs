FlowEngine - Engine Loop

Implementation reference for the core engine loop, background services, and DI registration.

Overview

The core engine loop - the orchestrator that takes an ExecutionInstance from one stable state to the next. Every node executor, state store and background service depends on it.

This page describes what the current code does, step by step, and names the source file and method for each behavior. Internal code is summarized rather than reproduced; read the cited method for the exact logic. Public API listings match EF.FlowEngine/PublicAPI.Shipped.txt.

Source: FlowEngine.cs, constructor. A null circuitBreakerStore disables circuit breaking. The constructor also:

  • creates the global execution semaphore when MaxConcurrentExecutions > 0;
  • takes the host stopping token from IHostApplicationLifetime.ApplicationStopping (none when not registered); background executions and follow-ups run on it;
  • resolves the optional IOutboxStore, IIntakeQueue and IDeadLetterStore from services. With a dead-letter store registered (UseDeadLetterStore), every instance that ends Faulted is enqueued to it (see FinishTerminalAsync).

Internal tracking state:

  • ActiveExecutions - ConcurrentDictionary<string, LocalExecution> of executions running in this process; LeaseRenewalService renews their leases and CancelAsync stops them.
  • UnexitedExecutions, InFlightCancels, InFlightFollowUps - what the shutdown drain waits for. An execution leaves ActiveExecutions before its final save, so the drain waits on UnexitedExecutions instead.
  • A per-instance record gate (WithRecordGateAsync) serializes signal callers on one instance in this process, so their saves do not keep conflicting.

StartAsync

Source: FlowEngine.cs, StartAsync. Runs synchronously until the instance suspends, completes or faults.

  1. ValidateStartRequest - length checks where the identifiers enter, so an over-long value fails here rather than at a SQL insert: CorrelationId at most MaxCorrelationIdLength (64), TenantId at most MaxTenantIdLength (128), ParentInstanceId at most MaxInstanceIdLength (64), IdempotencyKey at most MaxTagValueLength (512), and each tag through ValidateTag (key at most 256, value at most 512, neither null). Lengths are UTF-16 code units; a violation throws ArgumentException. TenantId and IdempotencyKey must also be well-formed UTF-16: a lone surrogate would hash like U+FFFD and alias another key.
  2. Instance id and idempotency (NewInstanceId) - without an IdempotencyKey (null or empty) the id is a new N-format GUID. With one, the id is the first 32 hex characters of SHA-256 over (TenantId, key), the tenant length-prefixed and a null tenant kept apart from "". An instance already stored under that id is loaded and returned instead of starting a new one. Because every store's first save of an id is create-only, the id makes the store enforce at most one instance per (tenant, key), even for concurrent starts on several hosts. Keys are scoped to the tenant, not the workflow. After the instance is deleted or purged the key starts a new instance with the same id; children of the old instance still name it as their parent but are ignored by the new one (created before it), and a lease left by the old instance blocks the restart until it expires.
  3. Admission (AdmitStartAsync, the next four steps). When one of them throws for a keyed start, the id is loaded again and an instance found there (a concurrent start that filled the quota, say) is returned instead.
  4. Tenant quota (EnforceTenantQuotaAsync) - when the request has a tenant and TenantPolicies resolves a MaxConcurrentInstances cap, counts the tenant's Running, Suspended and Queued instances and throws WorkflowCapacityExceededException at or over the cap. A child started from inside its running parent's execution in this process (same tenant) is exempt. Best effort: concurrent starts can briefly overshoot.
  5. Load the definition - IWorkflowRegistry.GetAsync(request.WorkflowId, request.WorkflowVersion); missing throws WorkflowNotFoundException. A non-Active definition throws WorkflowNotActiveException unless request.AllowDraft is set. With AllowDraft and no version, the highest non-Archived version of that exact id is loaded instead, since registry latest lookups return Active versions only.
  6. ValidateWorkflowDependenciesAsync (below).
  7. Params schema - when the definition has a ParamsSchema, ParamsSchemaValidator.Validate runs on request.Params; errors throw ArgumentException.
  8. Create the instance - the id from the step above, Status = Running, CurrentNodeId = EntryNodeId, TenantId, CorrelationId, Deadline, parent ids, tags merged from DefaultTags and request.Tags (MergeTags, which validates them), and the idempotency tag (ApplyIdempotencyTag).
  9. SaveClaimedNewAsync - takes the lease with TryAcquireNewAsync, stamps the claim on the record, then saves it, so no reader ever sees the instance Running and unclaimed (the sweep would run it a second time). A refused lease throws InvalidOperationException. A failed save releases the lease through ReleaseNewAsync, which releases only what TryAcquireNewAsync took (nothing for the SQL lock, whose lease lives on the record that, after a conflict, is the winner's). For a keyed start, a refused lease or a ConcurrencyException on the save means a concurrent start with the same key won the id, and LoadIdempotencyWinnerAsync returns the winner. The winner takes its lease before its first save, so it can briefly hold the id without a record: the load retries with doubling delays (20 ms to 640 ms, about 1.3 s in total), then throws ConcurrencyException whose message says whether the lease was refused or the record existed; retrying the start returns the winner.
  10. Emits flow.instance.started and runs ExecuteLoopAsync(instance, ct, leaseHeld: true, newStart: true).

StartBackgroundAsync runs the same validation and resolves the definition the same way as StartAsync: GetAsync(id, version), Active only unless AllowDraft; with AllowDraft and no version (a dashboard test run) it takes the highest non-Archived version of that exact id from ListAsync. With an IIntakeQueue registered it saves the instance Queued (a keyed start that loses the save returns the winner through LoadIdempotencyWinnerAsync), emits flow.instance.queued, enqueues it and returns; otherwise it saves claimed, emits flow.instance.started, starts the loop on the thread pool with the host stopping token and returns a snapshot. StartManyAsync calls StartAsync for each request concurrently (Task.WhenAll).

ValidateWorkflowDependenciesAsync

Source: FlowEngine.cs, ValidateWorkflowDependenciesAsync. Runs before any instance starts:

  1. WorkflowDefinitionValidator.ValidateAndThrow(definition).
  2. Logs a warning for each UnsafeRetryWithoutIdempotencyHeader warning from GetWarnings.
  3. Throws ArgumentException when the definition's DefaultLeaseDuration is not longer than LeaseRenewalInterval (the lease would lapse between renewals).
  4. ValidateSecurityPolicy(definition, options) (for example AllowComputeNodes, AllowWhenExpressions); errors throw ArgumentException.
  5. ValidateClients(definition, clientRegistry); errors throw WorkflowDefinitionValidationException (Details code CLIENT_NOT_REGISTERED). This is a guard: registries registered through FlowEngineBuilder already reject unregistered clientRefs at save and at startup seeding.
  6. Calls ValidateAsync on every distinct referenced client; a failure throws ClientValidationException.

MissingClientException is still thrown by executors when a client is missing at run time.

Resume paths

ResumeAsync / ResumeBackgroundAsync - look up the instance with FindBySuspendedEventAsync(eventName, correlationKey). On a miss they load by instanceId: missing throws InstanceNotFoundException; an instance no longer suspended (or without a wait) is returned as is (idempotent); a suspended instance whose wait did not match throws InstanceNotFoundException. A found instance that is not Suspended, or has no PendingWait, is returned as is. Otherwise both call ResumeSuspendedAsync.

ResumeByInstanceIdAsync / ResumeByInstanceIdBackgroundAsync - load by id (missing throws InstanceNotFoundException), return a non-Suspended instance as is, otherwise call ResumeSuspendedAsync. Human task stores resume through this path (section 15).

ResumeSuspendedAsync (source: FlowEngine.cs). Under the instance's record gate it first tries to claim the instance and apply the signal (TryTransitionClaimedAsync); if the lease is held elsewhere it still saves the signal accumulation only (SaveTransitionAsync with canRun: false), so losing the claim never loses a signal. The transition (re-applied on each concurrency retry) follows these rules:

  1. Stale suspension - the signal is dropped unless the instance is still Suspended at the same node with the same wait event name and correlation key the caller saw.
  2. Human task mismatch - a JSON object payload carrying _humanTaskId is dropped unless that id equals the instance's PendingHumanTaskId, so a completed task's response cannot advance a later suspension.
  3. Open-circuit wait - a wait for an open circuit is not a wait node: the signal is never accumulated and its payload never reaches the context. Before the cool-down (TimeoutAt in the future), or when the instance cannot be claimed, it is ignored and logged; after the cool-down a claiming signal re-runs the node, as the sweep would.
  4. Accumulate - the payload (or an empty object) is appended to a new copy of PendingWait.ReceivedSignals and LastSignalHasPayload is recorded. Below MinSignalCount, or without the claim, the accumulation is saved and the call returns.
  5. Past deadline - when the instance deadline has passed and is not yet handled (DeadlineHandledAt null), the node is not advanced and the signal is not applied: the pending human task is cancelled (CancelAbandonedTaskAsync), the wait and task pointer are cleared, and the instance goes Running so the loop's deadline check decides.
  6. Advance - otherwise AppendSignalToContext writes the payload and AdvancePastCurrentNodeAsync(Match) moves past the suspension node.

After the transition: a terminal result saved without the lease (an edgeless suspension node completes the instance) gets its follow-ups from FinishTransitionTerminalAsync; a Running result emits flow.instance.resumed, restores the trace context captured at suspension (foreground only) and runs ExecuteLoopAsync with the lease held. The background variants return a snapshot and run the loop on the thread pool.

2. ExecuteLoopAsync - the main loop

Source: FlowEngine.cs, ExecuteLoopAsync(instance, hostCt, leaseHeld, newStart, claimOperation). The instance's tenant is set as the ambient tenant (TenantExecutionScope) for the whole call.

Admission

  1. Per-workflow cap - with a PerWorkflowConcurrencyLimits entry, a slot is taken without waiting; none free throws WorkflowCapacityExceededException (always reject).
  2. Global cap - with MaxConcurrentExecutions > 0: GlobalOverflowPolicy.Reject throws WorkflowCapacityExceededException when no slot is free; Block waits on the host token.
  3. On a rejection, RejectAdmissionAsync releases a lease the caller still owns; for a new start (newStart) it first saves the instance Faulted with CAPACITY_EXCEEDED and its claim cleared, so the sweep never runs it later.

Phase 1 - claim

The lease is exclusive (a lease held by anyone, this process included, refuses it). A caller that already holds it (leaseHeld) confirms it with RenewAsync; otherwise, or if it lapsed, TryAcquireAsync. Not claimed, or already in ActiveExecutions: release the slots and return the instance unchanged. Claimed: a LocalExecution (linked token source, enclosing execution, lease timestamps) is registered in ActiveExecutions and UnexitedExecutions and becomes LocalExecution.Current, which flows into node executors and children they start inline.

Phase 2 - load

Reloads the instance. Missing, terminal, or (for a leaseHeld caller) no longer Running means someone else moved it on: the execution is undone (ReleaseUnstartedAsync) and the stored state returned. The loaded Version is recorded as execution.SavedVersion. Then:

  • Missing definition (or an instance already carrying DEFINITION_NOT_FOUND): fault with DEFINITION_NOT_FOUND, save, and go to phase 4.
  • A per-workflow DefaultLeaseDuration different from the option renews the lease to that length, which the renewal service then uses.
  • Claim fields are stamped on the instance and queued child signals are dequeued (executors read their children's state through GetChildrenAsync).

Phase 3 - node loop

Each iteration first checks the execution token. One compensationAttempted set per run means a later unwind compensates only what ran since an earlier one.

  1. Saved failure unwind - when Error.Code is FAILURE_UNWIND_PENDING (a checkpoint saved before compensation, step 3i), the unwind resumes before any forward node or deadline handler: RunCompensationAsync when compensation is enabled, the marker is cleared, and FinishUnhandledNodeAsync runs with the outcome and error of the last failed forward record. A current node missing from the definition faults with NODE_NOT_FOUND. The failed node is never re-executed.
  2. 3a. Instance deadline - when the deadline has passed and is not yet handled:
    • With GlobalOnDeadlineNodeId set and the handler never entered (DeadlineHandlerEnteredAt null): cancel any pending human task (CancelAbandonedTaskAsync; a failure stops the run and leaves the instance for a retry), set DeadlineHandledAt and DeadlineHandlerEnteredAt, route to the handler, clear the wait and task pointer and any WAIT_TIMEOUT error, and continue. The handler runs at most once.
    • Otherwise: cancel open human tasks and non-terminal children (CancelBeforeTimeoutUnwindAsync), run compensation when enabled, clear the wait, set DeadlineHandledAt, and end TimedOut with INSTANCE_DEADLINE_EXCEEDED.
  3. 3a-wait. Handed-over wait timeout - when Error.Code is WAIT_TIMEOUT on a Running instance (the sweep hands over an unhandled wait timeout of a saga, section 17): cancel tasks and children, compensate when enabled, and end TimedOut. After 3a, so a deadline that passed meanwhile wins.
  4. 3b. Load node - missing faults with NODE_NOT_FOUND.
  5. 3c. MaxVisits - the visit count is incremented. Over MaxVisits ends CycleDetected with MAX_VISITS_EXCEEDED, except for a re-run after an open-circuit wait (lastCircuitRetry): that one still runs, since the circuit may just have closed.
  6. 3c-req. Context requirements - unmet ContextRequirements produce an Error result CONTEXT_REQUIREMENTS_FAILED without running the node.
  7. 3d. Execute - emits flow.node.started and calls ExecuteWithRetryAsync (section 3). The global failure and deadline handler nodes bypass an open circuit. If lastCircuitRetry meets the open circuit again, the result becomes an Error CIRCUIT_OPEN_RETRIES_EXHAUSTED: the dependency stayed down, which fails the node (Error edge, compensation, global failure node) rather than reporting a definition cycle. Emits flow.node.completed with the duration.
  8. 3d-keys. Run-time keys - OversizedRunTimeKey checks values resolved at run time against the stores' bounded columns: the wait event name (256) and correlation key (256), and each pending outbox entry's instance id (64), node id (64), client ref (127) and idempotency key (512). The first one too long replaces the result with an Error RUNTIME_KEY_TOO_LONG, which also drops the result's outbox entries. A message the executor already sent directly cannot be recalled.
  9. The result's pending outbox entries are buffered; they are written with the next save.
  10. 3d-out. Output schema - for a non-Error result with StoreAs and OutputSchema, a JSON output that fails validation becomes an Error OUTPUT_SCHEMA_VALIDATION_FAILED.
  11. 3e. storeAs - a non-null output is stored under StoreAs.
  12. 3f. History record - built with timing, outcome, output snapshot, HTTP status, attempt count, error and metadata.
  13. 3g. Suspension - a result with PendingWait sets the wait (capped at an unhandled deadline by CapAtDeadline, so the sweep finds the instance then), PendingHumanTaskId, Status = Suspended and the W3C trace context, records BranchTaken = "suspended", emits flow.instance.suspended and goes to phase 4.
  14. 3h. Edge evaluation - the first edge whose On is empty or contains the outcome, and whose When (if any) evaluates truthy, wins.
  15. 3i. No matching edge:
    • A node without edges and an outcome other than Error or CircuitOpen (EndsWorkflow) completes the instance with the node's output.
    • CircuitOpen: suspend on the wait event circuit.{key}.reopen (key defaults to the node type), correlation key = instance id, timeout = now + the policy's OpenDuration (default policy when the node has none), capped at the deadline; BranchTaken = "circuit-open".
    • Error with EnableCompensation: set Error to FAILURE_UNWIND_PENDING, save (a checkpoint of the intent and the failed step before any compensation side effect), and continue; the next iteration runs the unwind (step 1). A save that finds the record already final stops the run.
    • Otherwise FinishUnhandledNodeAsync (below).
  16. 3j. Advance - CurrentNodeId = next node.
  17. 3k. Checkpoint - when the result has ForceCheckpoint (emits flow.checkpoint.saved) or the definition sets PersistAfterEveryNode, the token is checked (a stopped execution must not save) and SaveWithRetryAsync persists the instance and buffered outbox entries; the claim is kept and the loop continues. Without either, sequential synchronous nodes run with no intermediate save.

FinishUnhandledNodeAsync (source: FlowEngine.cs) decides an unhandled outcome; it returns true when the loop continues at the global failure node:

csharpprivate static async Task<bool> FinishUnhandledNodeAsync(
    ExecutionInstance instance, WorkflowDefinition definition, NodeDefinition node,
    DecisionOutcome outcome, ExecutionError? error)
{
    if (outcome == DecisionOutcome.Error && definition.GlobalOnFailureNodeId != null
        && node.Id != definition.GlobalOnFailureNodeId)
    {
        instance.CurrentNodeId = definition.GlobalOnFailureNodeId;
        return true;
    }
    if (node.Edges.Count == 0 || error?.Code == CircuitRetriesExhausted)
        await FaultInstanceAsync(instance, error?.Code ?? "NODE_FAILED",
            error?.Message ?? $"Node '{node.Id}' failed and has no outgoing edges", node.Id);
    else
        await FaultInstanceAsync(instance, "NO_MATCHING_EDGE",
            $"No edge matched outcome '{outcome}' from node '{node.Id}'", node.Id);
    return false;
}

Exceptions inside the loop

  • OperationCanceledException while the host is running - a per-node timeout (already turned into a result) or a stop from outside (CancelAsync, lost lease); phase 4 handles it.
  • OperationCanceledException from host shutdown - the instance stays Running for the sweep.
  • Any other exception - logged and the instance faulted with ENGINE_ERROR, unless it carries FAILURE_UNWIND_PENDING, which stays Running with its intent intact for recovery.

Phase 4 - exit paths

The execution is removed from ActiveExecutions, its slots are released, and exactly one of four paths runs; MarkExited runs last whatever happens.

  1. Cancel requested (execution.CancelRequested, set by CancelAsync) - the execution does not save its own outcome; the returned instance shows Cancelled, and it releases its lease unless it handed it over to the cancel.
  2. Finalized elsewhere - a save found the record already final, or the renewal service did (execution.FinalizedRecord, a cancel from another node). The stored outcome is reported, nothing is saved, and the lease is released.
  3. Stopped from outside - the token was cancelled while the host is running (the lease was lost). Nothing is saved; the sweep resumes from the last save.
  4. Normal - FinishExecutionAsync.

FinishExecutionAsync (source: FlowEngine.cs):

  1. Stamps UpdatedAt (and CompletedAt for a terminal state); clears the claim fields when Suspended or terminal.
  2. CancelTerminalHumanTasksAsync - for TimedOut, Faulted and CycleDetected, cancels open human tasks before the terminal save, since a record-backed lock releases on that save and a replay must not adopt this run's tasks.
  3. SaveWithRetryAsync with the outbox buffer, uncancellable. If the record was finalized elsewhere, release the lease and stop: that writer owns the follow-ups.
  4. Releases the lease when Suspended or terminal.
  5. Terminal: FinishTerminalAsync. Otherwise emits the final event; when Suspended, peeks queued child signals and, if one is for the node the parent now waits at, starts a new execution on the thread pool.

FinishTerminalAsync - emits the final event (flow.instance.completed, faulted, timed_out or cancelled; CycleDetected emits faulted), enqueues a Faulted instance to the dead-letter store when one is registered (failures logged), signals the parent of a child instance, and in a finally cancels the non-terminal children of a TimedOut or CycleDetected instance. A Faulted instance keeps its children, because a dead-letter replay re-runs the failed node and its executor adopts the existing children.

3. ExecuteWithRetryAsync

Source: FlowEngine.cs, ExecuteWithRetryAsync(node, instance, definition, ct, bypassOpenCircuit).

  1. Policy = node.RetryPolicy ?? definition.DefaultRetryPolicy; clock = the registered TimeProvider, else TimeProvider.System; circuit policy = CircuitPolicyFor (the node's policy, else the workflow default, which does not apply to output nodes). A node type with no executor throws NodeExecutorNotFoundException.
  2. Circuit check - with a circuit policy and store, and not bypassing: an open circuit (key = policy key, else node type) returns a CircuitOpen result CIRCUIT_OPEN with attempt count 0, without running the node.
  3. Per-node-type slot - with MaxConcurrentNodeExecutions > 0, each attempt holds a slot of a semaphore shared by that node type.
  4. Attempts - NodeAttempts.RunAsync. Per attempt it applies node.ExecutionTimeout (NODE_EXECUTION_TIMEOUT), maps executor exceptions to NODE_EXECUTOR_EXCEPTION, fails with RETRY_AFTER_LIMIT_EXCEEDED (not resent) when Retry-After exceeds the cap, and decides whether to retry: non-integration nodes when policy.RetryOn contains the outcome or the HTTP status is in policy.RetryOnHttpStatus; integration nodes by status list (never 2xx or 412; config.RetryOnStatusCodes replaces the inherited list; unsafe methods without idempotencyKeyHeader use only 409/429/503), plus INTEGRATION_TRANSPORT_ERROR / NODE_EXECUTION_TIMEOUT for safe methods or when idempotencyKeyHeader is set. The wait is max(backoff, Retry-After) on the clock.
  5. Circuit recording - not when bypassing. An Error or CircuitOpen result calls RecordFailureAsync; any other calls RecordSuccessAsync, and when that closes the circuit WakeCircuitWaiters resumes, in the background, every instance suspended on circuit.{key}.reopen (paged by id, at most 8 resumed executions at once, one wake per key with a rerun if another closing arrives meanwhile).

Saga compensation (RunCompensationAsync) walks the history newest first and runs each forward node's CompensationNodeId once per run, past any open circuit. It skips Error and CircuitOpen records, migration markers, compensation records, and nodes already compensated (a CircuitOpen compensation does not count). A missing node or compensation node, or a compensation that fails or reports CircuitOpen, emits flow.compensation.incomplete; a thrown exception is recorded as COMPENSATION_ERROR and does not stop the unwind. Each compensation step is appended to history with CompensatingFor set.

4. WhenEvaluator

Source: WhenEvaluator.cs. A DI singleton that evaluates when guards, compute expressions and correlation key expressions as Roslyn C# scripts (not JSONPath). Scripts are compiled once and cached by expression, up to ScriptCacheSize entries (default 1000; at capacity 10% of entries are evicted). Imports System, System.Linq, System.Collections.Generic and System.Text.Json. A bare expression is wrapped in return (object)(...);.

csharppublic class Globals
{
    public IReadOnlyDictionary<string, ContextVal> Context { get; set; } = null!;
    public IReadOnlyDictionary<string, object?> Engine { get; set; } = null!;
    public IReadOnlyDictionary<string, object?> Entity { get; set; } = null!;
    public IReadOnlyDictionary<string, object?> Params { get; set; } = null!;
}
  • Context values are ContextVal: a string indexer (Context["outer"]["inner"]) and ToString() (empty string for null), nothing else. Casts such as (int)Context["x"] do not compile; compare strings or parse, for example Context["_humanTaskConsensus"].ToString() == "unanimous".
  • Engine holds instanceId, workflowId, currentNodeId, status, visits (a Dictionary<string, int>) and totalVisits.
  • Entity is the entity deserialized one level to a Dictionary<string, object?> whose values are boxed JsonElements (not unwrapped CLR values), so parse their ToString(). Params holds the start parameters and Context the context values, both recursively unwrapped: JSON numbers become int, long, double or decimal; objects become Dictionary<string, object?>.
  • EvaluateAsync returns truthiness (non-null, non-false, non-zero int, non-empty string); EvaluateAsStringAsync returns ToString(); EvaluateAsObjectAsync returns the raw value.
  • Each run executes on the thread pool raced against ScriptTimeoutSeconds (default 5; 0 disables); a timeout throws TimeoutException. The timeout bounds the wait only: the running script is not cancelled and keeps its pool thread until it finishes.

5. RetryHandler

csharppublic static class RetryHandler
{
    private static readonly Random _jitter = new();

    public static TimeSpan CalculateDelay(RetryPolicy policy, int attemptNumber)
    {
        var attempt = attemptNumber - 1; // 0-based exponent

        TimeSpan delay = policy.Backoff switch
        {
            BackoffType.Fixed => policy.InitialDelay,
            BackoffType.Linear => policy.InitialDelay * attemptNumber,
            BackoffType.Exponential => policy.InitialDelay * Math.Pow(2, attempt),
            BackoffType.ExponentialWithJitter =>
                policy.InitialDelay * Math.Pow(2, attempt)
                + TimeSpan.FromMilliseconds(_jitter.Next(0, 1000)),
            _ => policy.InitialDelay
        };

        return delay > policy.MaxDelay ? policy.MaxDelay : delay;
    }
}

6. ChildSignalHandler

Source: ChildSignalHandler.cs, SignalParentAsync. Called when a child instance reaches a terminal state (from FinishTerminalAsync, and from CancelAsync when the parent is not terminal).

  1. A child without ParentInstanceId or ParentNodeId is logged and ignored.
  2. Builds a ChildSignal (parent node id, child id, status, output, time).
  3. Unless the host is stopping, tries to take the parent's lease as child-signal-{childInstanceId} for 30 seconds.
  4. Claimed: engine.ResumeChildAsync, which enqueues the signal, releases the child-signal lease, reloads the parent and, via TryTransitionClaimedAsync, sets it Running and runs the loop - only if the parent is still at the spawning node (otherwise another resume already consumed the signal).
  5. Not claimed (or the host is stopping): enqueues the signal uncancellably, and gives back a lease the acquire may have taken around the stop. The sweep later resumes a parent with queued signals.

7. ExecutionSweepService

Source: ExecutionSweepService.cs.

  • Startup - waits a random 0 to 5 seconds, then runs SweepAsync every SweepInterval; an iteration failure is logged.
  • Resumable instances (FindResumableCandidatesAsync) - IDistributedLockProvider.FindResumableInstanceIdsAsync(cutoff, requested, SweepPartitionCount, SweepPartitionIndex). The provider API has no cursor, so the service reads a growing prefix and takes the next SweepBatchSize ids after an offset kept across passes, wrapping to the start after the end.
  • Queued child signals (FindParentsWithQueuedSignalsAsync) - a separate pass whose failure never affects the first: one page (max(SweepBatchSize * 5, 50)) of FindInstancesWithChildSignalsAsync after a cursor kept across passes, skipping ids already resumed this pass, ids outside this partition, and instances that are Running or Queued; at most SweepBatchSize ids.
  • Resumption - each id is resumed with FlowEngine.ResumeFromSweepAsync on the thread pool, bounded by a semaphore of MaxConcurrentExecutions (or SweepBatchSize when unlimited).

ResumeFromSweepAsync (source: FlowEngine.cs):

  • Missing or terminal: drains and drops its queued child signals.
  • Case 1 - Running (its claim expired: a crash): re-executes from the saved state. Node executors must be idempotent.
  • Suspended without a wait: drops queued child signals and returns. Queued instances are not swept.
  • Otherwise a transition under TryTransitionClaimedAsync (the lease is taken and the change saved before anything else; with the lease held elsewhere nothing changes):
    • Case 2 - enough signals accumulated: past an unhandled deadline, the wait and task are dropped and the instance goes Running for the loop's deadline check; otherwise the last payload is applied (unless it had none) and the node is advanced with Match.
    • Case 2b - queued child signals: one for the current node sets Running (the node re-runs and reads its children); signals only for nodes the parent has left are drained and dropped.
    • Case 3 - wait timed out: see section 17.
  • A transition that routes away from a human wait cancels that task (CancelAbandonedTaskAsync) inside the transition; if that fails, the transition is not applied and the sweep retries. A Running result runs the loop with the lease held; a terminal result gets FinishTransitionTerminalAsync.

8. LeaseRenewalService

Purpose: keeps the leases of executions running locally alive, so other nodes' sweeps do not reclaim them, and stops a local execution whose record another node finalized.
Interval: FlowEngineOptions.LeaseRenewalInterval (default 13s), which must be shorter than every lease (a workflow DefaultLeaseDuration not longer than it is rejected at start).
Source: LeaseRenewalService.cs, RenewLeasesAsync.

  1. Snapshots ActiveExecutions and renews every lease in parallel (at most 16 at once) with the execution's own lease duration (LocalExecution.LeaseDuration, else DefaultLeaseDuration). Executions already stopped by CancelAsync are still renewed, so the lease does not lapse under a node that ignores cancellation.
  2. RenewAsync returning false cancels the execution's token. A provider exception keeps the execution running only while the lease still outlasts the next attempt; otherwise it is cancelled too.
  3. For every lease that held, one batched GetStatusesAsync read: a record that is final at a version this execution did not write (and is not writing its own outcome) is reloaded, stored on execution.FinalizedRecord, and the execution is cancelled. It then saves nothing (phase 4, path 2). A read failure is logged and retried next pass.

11. MigrateInstanceAsync / MigrateInstancesAsync / DeleteWorkflowVersionAsync

MigrateInstanceAsync (source: FlowEngine.cs):

  1. Loads the instance (missing throws InstanceNotFoundException); a terminal instance throws InvalidOperationException, as does a missing target version.
  2. Resolves the current node through nodeIdMap; a node missing from the target version throws InvalidOperationException.
  3. Builds a history record with node type migration, label Migrated {from} -> {target} (written in the code with an arrow character, plus [dry-run] for a dry run), and metadata migratedFromNodeId = the node it moved from, so an open-circuit wait recorded under the old id is still recognised.
  4. dryRun applies everything to a snapshot and returns it without saving, so the loaded (possibly shared) instance is untouched.
  5. An open-circuit wait is re-keyed to the circuit the target node would wait on (circuit.{key}.reopen), keeping its timeout.
  6. Sets the version, remaps visit counts with RemapVisitCounts (a renamed node keeps its count; a merge keeps the larger), sets the current node, appends the record and saves.

MigrateInstancesAsync queries up to maxInstances instances of workflowId@fromVersion, migrates each non-terminal one, and reports Migrated ids and Failed messages in a BulkMigrationResult (with TotalConsidered and DryRun).

DeleteWorkflowVersionAsync throws InvalidOperationException when the version has any Running or Suspended instance, transitions an Active definition to Draft, then calls IWorkflowRegistry.DeleteAsync.

ReplayFromDeadLetterAsync requires a registered IDeadLetterStore (else InvalidOperationException), claims the instance and sets it Running with the error cleared (only if its status and node are unchanged), removes it from the dead-letter store, and runs the loop, which re-runs the failed node.

14. CancelAsync

Source: FlowEngine.cs, CancelAsync / CancelCoreAsync. The call is registered in InFlightCancels until it returns. All waits share one deadline of DefaultLeaseDuration.

  1. Stop a local execution - if the instance runs in this process, StopLocalExecutionAsync flags it (CancelRequested, so it never saves its own outcome), cancels its token and waits for it to exit (not when the call comes from inside that execution, which would wait on itself). Stopped from outside before it committed to releasing, it hands its lease over to the cancel. From here the caller's token is no longer used.
  2. Claim - adopt the handed-over lease (AdoptLeaseAsync: renew, else acquire) or try to acquire it. Up to three times more, any other local execution of the instance that appeared meanwhile is stopped the same way.
  3. Load a copy (missing throws InstanceNotFoundException); a terminal instance is returned as is (idempotent).
  4. Save - Status = Cancelled, CompletedAt, Error = CANCELLED with the reason, PendingWait cleared; SaveWithRetryAsync. If another writer finalized the record meanwhile, return: that writer owns the follow-ups. Otherwise emit flow.instance.cancelled.
  5. Human tasks - cancel the instance's Open and InProgress tasks (failure logged, not thrown).
  6. Children - cancel non-terminal children recursively, best effort (each failure logged).
  7. Parent signal - a child whose parent is not terminal signals it (ChildSignalHandler.SignalParentAsync), so a loop, parallel or workflow node waiting on it moves on.
  8. Release (in finally) - the lease is released when claimed or handed over, unless another local execution, or a claim in progress, now owns it.

An execution on another node is stopped by that node's LeaseRenewalService once it reads the Cancelled record (section 8).

15. HumanNodeExecutor

Source: EF.FlowEngine/Executors/HumanNodeExecutor.cs, ExecuteAsync. It requires a registered IHumanTaskStore.

  1. Reuse - if the store holds a task for this instance and node that is Open or InProgress, it re-suspends on that task (no duplicate). A Completed or Cancelled task is not reused: a re-run opens a fresh task.
  2. Resolve fields - DueIn through ResolveDateTimeAsync (an unresolvable value leaves no due date); Title by {{$.path}} interpolation; AssignedTo as a direct $. path, else by interpolation. An unresolved path keeps the literal text.
  3. Assignee length - an assignee longer than MaxAssignedToLength (256) returns an Error result ASSIGNEE_TOO_LONG without creating a task (the stores index that column).
  4. Create - a task with a new id, title, description, assignee, channel, notification, form schema, visible context, quorum, due date, escalation, Status = Open and a snapshot of the visible context keys, saved to the store.
  5. Suspend - returns Match with HumanTaskId = task id and this wait:
csharpPendingWait = new WaitDescriptor
{
    EventName = $"human.{instance.InstanceId}.{node.Id}",
    CorrelationKey = task.TaskId,
    TimeoutAt = task.DueAt,
    OnTimeoutNodeId = config.OnTimeoutNodeId,
    MinSignalCount = 1   // quorum is enforced by the task store
}

The engine records the task id as PendingHumanTaskId. A due date routes like any wait timeout (section 17); a route away from the wait cancels the task.

How SubmitResponseAsync wires back to the engine

IHumanTaskStore.SubmitResponseAsync(taskId, responseToken, formValues, respondedBy, ct) records the response and, once the quorum is reached and the task is Completed, resumes the instance (see InMemoryHumanTaskStore.SubmitResponseAsync):

csharpvar signal = HumanTaskContextKeys.BuildSignalPayload(task);
await engine.ResumeByInstanceIdAsync(task.InstanceId, signal, ct);

BuildSignalPayload carries _humanTaskId, _humanTaskResponse (the first response), _humanTaskResponses (all responses) and _humanTaskConsensus (null for a quorum of 1). ResumeSuspendedAsync accepts it only when _humanTaskId equals the pending task, and AppendSignalToContext promotes the three response keys into the context. The human node is not re-executed: the engine advances past it with Match.

16. File State Store

Source: EF.FlowEngine.StateStore.File/FileExecutionStateStore.cs. Development and single-process testing only.

  • Layout - under the root directory: instances/{instanceId}.json per instance, and signals/{parentInstanceId}/{guid}.json per queued child signal. JSON uses JsonSerializerDefaults.Web.
  • Version rule (SaveAsync) - under one lock per store instance: when the file exists, its stored Version must equal instance.Version, else ConcurrencyException; the store then increments instance.Version and writes. Another process on the same directory is not excluded.

17. TimerNodeExecutor and wait-timeout routing

Source: EF.FlowEngine/Executors/TimerNodeExecutor.cs. Resolves Delay through ICalendarProvider (via ResolveDateTimeAsync); if that throws it tries TimeSpan.TryParse, else waits 30 seconds. It emits no telemetry of its own and returns Match with this wait:

csharpPendingWait = new WaitDescriptor
{
    EventName = $"timer.{instance.InstanceId}.{node.Id}",
    CorrelationKey = instance.InstanceId,
    TimeoutAt = expiresAt,
    MinSignalCount = 1
}

Wait timeout in the sweep

Source: FlowEngine.cs, ResumeFromSweepAsync, case 3. When PendingWait.TimeoutAt has passed, branches apply in this order:

  1. Deadline - the instance deadline passed and is unhandled (the wait's timeout was capped at it on suspend): drop the wait and task and set Running; the loop's deadline check (3a) routes to the deadline handler or unwinds and times out.
  2. Open circuit - the cool-down is over: re-run the node (each re-run counts as a visit, so MaxVisits bounds how many cool-downs it waits out).
  3. Timer node - the delay is the happy path: advance with Match.
  4. Wait, human or message node - route to the wait's OnTimeoutNodeId; else to GlobalOnDeadlineNodeId if the deadline handler was never entered (this sets DeadlineHandlerEnteredAt but does not mark the deadline handled, which 3a still enforces); else WAIT_TIMEOUT:
    • with EnableCompensation the instance goes Running with that error, and the loop (3a-wait) unwinds under the claim and ends TimedOut;
    • without it the instance ends TimedOut directly.

No timeout flag is written to the context; a workflow reacts to a timeout through OnTimeoutNodeId or the deadline handler.

19. Behavior checklist

  • StartAsync validates the request, honors the idempotency key and tenant quota, saves the instance claimed, and returns it completed, suspended or faulted.
  • Sequential synchronous nodes run with no intermediate save unless a checkpoint node or PersistAfterEveryNode forces one.
  • A node returning PendingWait suspends the instance and releases the lease after the save.
  • A node without edges completes the instance, unless its outcome is Error or CircuitOpen.
  • MaxVisits breach ends CycleDetected; a re-run after an open-circuit wait probes once more, then fails with CIRCUIT_OPEN_RETRIES_EXHAUSTED.
  • An unhandled deadline routes once to GlobalOnDeadlineNodeId, else unwinds and ends TimedOut.
  • An unhandled Error routes to GlobalOnFailureNodeId; with compensation the unwind intent is saved first (FAILURE_UNWIND_PENDING) and resumed after a crash without re-running the failed node.
  • Signals accumulate in PendingWait.ReceivedSignals up to MinSignalCount; only the threshold-reaching payload is written to $.context._signal and appended to $.context._signals.
  • SaveWithRetryAsync returns false when it finds the record already final, and the execution then stops without overwriting it.
  • CancelAsync stops a local execution first, saves Cancelled, then cancels human tasks, children and signals the parent; it is idempotent.
  • A human node reuses only an Open or InProgress task and rejects an over-long assignee with ASSIGNEE_TOO_LONG.
  • An over-long run-time wait key or outbox field fails the node with RUNTIME_KEY_TOO_LONG.

20. ExecutionContext

Source: EF.FlowEngine/Impl/ExecutionContext.cs. Built per node execution by FlowEngine.BuildExecutionContext from the instance, the service provider, the registered ICredentialStore, IDocumentStore and ICalendarProvider, and the engine logger; all attempts of one node execution share it.

  • Resolve(jsonPath) supports $.engine.visits.{nodeId} (and $.engine.visits._total), $.engine.{field} (instanceId, workflowId, workflowVersion, status, createdAt, currentNodeId, parentInstanceId, correlationId; anything else resolves to a null value), $.entity and $.entity.a.b, $.params.key.a and $.context.key.a. Dot segments navigate JSON objects and numeric segments index arrays; a missing segment returns null. Any other namespace throws ArgumentException.
  • ResolveAs<T> deserializes a JSON value; a null or missing value returns default; any other value type throws InvalidCastException.
  • Store(key, value) writes to the instance context.
  • TotalVisitCount and GetVisitCount(nodeId) read NodeVisitCounts.
  • GetCredentialAsync, GetDocumentAsync (passes the instance's tenant to the document store) and ResolveDateTimeAsync (relative to now) delegate to the injected services.

21. SaveWithRetryAsync

Source: FlowEngine.cs, SaveWithRetryAsync(instance, claimantId, ct, outboxBuffer), which returns Task<bool>.

  1. Saves through SaveWithOutboxAsync with the buffered outbox entries; on success copies the new Version back to the caller, clears the buffer and returns true.
  2. On ConcurrencyException (up to two reload rounds, then a final attempt that lets the exception propagate) it reloads. A missing record returns false. A terminal record written meanwhile (for example by CancelAsync) is adopted into the caller (status, completion time, error, output, version), the buffer is cleared, and it returns false.
  3. Otherwise it copies every field the execution owns onto the fresh record (status, version, node, timestamps, output, error, wait, task pointer, context, visit counts, history, trace context, claim). DeadlineHandledAt and DeadlineHandlerEnteredAt never go back to null, and a claim expiry another renewal extended is kept; both are written back to the caller.

22. Engine helpers and default implementations

Helper methods on FlowEngine

  • AdvancePastCurrentNodeAsync(instance, outcome, ct) - on an open-circuit suspension it only clears the wait and sets Running, so the node re-runs. A missing definition sets Running with DEFINITION_NOT_FOUND, which the loop then faults. An edgeless suspension node completes the instance. Otherwise the first matching edge (outcome and When) becomes the current node, and the wait and task pointer are cleared; no match faults with NO_MATCHING_EDGE.
  • AppendSignalToContext(instance, payload) - with a payload: copies the context, stores it under _signal, appends it to _signals, and for a JSON object promotes _humanTaskResponse, _humanTaskResponses and _humanTaskConsensus (a JSON null becomes a null value).
  • FaultInstanceAsync - sets Faulted, CompletedAt, UpdatedAt and Error; it does not save or emit (phase 4 does).
  • IsTerminal - Completed, Faulted, Cancelled, TimedOut, CycleDetected.
  • EmitEvent / EmitFinalEvent - no-op without telemetry; tags instanceId, workflowId, status, and when present tenantId, nodeId, nodeType, outcome, durationMs, taskId. Final event names: flow.instance.completed, faulted (also for CycleDetected), timed_out, cancelled, suspended, running, with the duration since creation when completed.

Default implementations

  • DefaultCalendarProvider (Impl/DefaultCalendarProvider.cs) - ResolveAsync(string expression, DateTimeOffset baseTime, CancellationToken ct = default) adds an ISO 8601 duration (XmlConvert.ToTimeSpan); any other expression throws ArgumentException. Register a custom ICalendarProvider for business days or calendar expressions.
  • DefaultCredentialStore (Impl/DefaultCredentialStore.cs) - reads FLOWENGINE_CRED_{REF}_{FIELD} environment variables; the canonical format is in FlowEngine-CoreSchema.
  • DefaultDocumentStore (Impl/DefaultDocumentStore.cs) - both OpenReadAsync(storeRef, tenantId, ct) and StoreAsync(content, fileName, contentType, tenantId, ct) throw NotSupportedException; register a real store with UseDocumentStore<T>().
  • LoggerFlowEngineTelemetry (Impl/LoggerFlowEngineTelemetry.cs) - IFlowEngineTelemetry.Emit(string eventName, Dictionary<string, object?> tags) written with ILogger.LogDebug. UseMetrics, UseMetricsAndTracing, UseActivitySourceTelemetry or UseTelemetry<T> replace it.
