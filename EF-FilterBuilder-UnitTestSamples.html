REF Entity Model

All tests operate on a five-level class hierarchy. Every level carries the same scalar properties (Id, Name, Value, Enum, Date) plus optional scalar navigation to the next level and an optional collection of the next level.

FIG 1 — Entity class hierarchy. Every level has both a scalar navigation property and a collection of the next level.

Property paths can be written as flat dot-notation traversing any mix of levels: "B.C.D.Name", "B.C.Dcol.Name", "Bcol.C.Dcol.E.Name". The library detects collection boundaries automatically.

CORE Deep Property Navigation 4 tests

These tests demonstrate that PropertyPath can reach arbitrarily deep into an object graph using dot notation, without any FilterSet nesting required. The path is decomposed at expression-build time.

sssAMatch1 Flat dot-path to a 4-level scalar: B.C.D.Name and B.C.D.Enum resolved by path decomposition alone.
Both filters independently traverse the full B→C→D path. No nesting in the FilterSet definition is required — the system decomposes the path at build time.
a => a.B.C.D.Name == "A1B1C1D1" && a.B.C.D.Enum == Enum1
var filterset = new FilterSet
{
    Operator = Operator.AND,
    Filters = [
        new Filter { PropertyPath = "B.C.D.Name", Operation = "eq", TestValue = "A1B1C1D1" },
        new Filter { PropertyPath = "B.C.D.Enum", Operation = "eq", TestValue = "Enum1" }
    ]
};
Assert.HasCount(1, match) — A1 matches; A2.B is null so null-guard returns false
sss2Match1 Explicit 2-level FilterSet nesting producing the same result as sssAMatch1.
Root Filter scopes to B; child FilterSet applies C.D.Name and C.D.Enum using dot-path remainders. Functionally identical to the flat path — shows the equivalence.
a => a.B.C.D.Name == "A1B1C1D1" && a.B.C.D.Enum == Enum1
var filterset = new FilterSet
{
    Operator = Operator.AND,
    Filters = [
        new Filter
        {
            PropertyPath = "B",
            FilterSet = new FilterSet
            {
                Operator = Operator.AND,
                Filters = [
                    new Filter { PropertyPath = "C.D.Name", Operation = "eq", TestValue = "A1B1C1D1" },
                    new Filter { PropertyPath = "C.D.Enum", Operation = "eq", TestValue = "Enum1" }
                ]
            }
        }
    ]
};
Assert.HasCount(1, match) — same result as sssAMatch1
sss3MatchSame1 Full 4-level explicit nesting — A→B→C→D each as a separate FilterSet boundary.
Every navigation level is explicitly scoped. This is the most verbose way to write a deep path filter and produces exactly the same compiled expression as the flat dot-path approach.
a => a.B.C.D.Name == "A1B1C1D1" && a.B.C.D.Enum == Enum1
// B scopes to C, C scopes to D, D scopes to leaf conditions
new Filter { PropertyPath = "B", FilterSet = new FilterSet {
    Filters = [ new Filter { PropertyPath = "C", FilterSet = new FilterSet {
        Filters = [ new Filter { PropertyPath = "D", FilterSet = new FilterSet {
            Operator = Operator.AND,
            Filters = [
                new Filter { PropertyPath = "Name", Operation = "eq", TestValue = "A1B1C1D1" },
                new Filter { PropertyPath = "Enum", Operation = "eq", TestValue = "Enum1" }
            ]
        }}]
    }}]
}}
Assert.HasCount(1, match) — same compiled expression, same result
Delimiter_SlashSeparated_DeepNavPath  ·  Delimiter_MultiChar_DeepNavPath  ·  Delimiter_MixedPerFilter_SameFilterSet Alternative and mixed delimiters on deep paths.
Delimiters are per-Filter and can be any string. All three examples below produce the same compiled expression as sssAMatch1.
// Slash delimiter on every segment
new Filter { PropertyPath = "B/C/D/Name", Delimiter = "/",  Operation = "eq", TestValue = "A1B1C1D1" }

// Multi-character arrow delimiter
new Filter { PropertyPath = "B->C->D->Name", Delimiter = "->", Operation = "eq", TestValue = "A1B1C1D1" }

// Mixed delimiters within the same FilterSet — each Filter is independent
new Filter { PropertyPath = "B/C/D/Name",   Delimiter = "/",  Operation = "eq", TestValue = "A1B1C1D1" },
new Filter { PropertyPath = "B::C::D::Enum", Delimiter = "::", Operation = "eq", TestValue = "Enum1"    }
Assert.HasCount(1, match) — identical result for all delimiter variants

CORE Collection Scope Disambiguation 8 tests

The most important structural concept in FilterBuilder. The presence or absence of a child FilterSet on the Filter targeting a collection property determines whether conditions must match the same element or can match different elements.

The paired tests below use identical conditions. Same data, same property paths, same values. Only the FilterSet structure differs — and the results are different. Read them side by side.

Pair 1 — B.C.Dcol: any-object vs same-object

Any-object scope — sscMatchAny1
Filters placed above the collection boundary in PropertyPath. Each generates its own independent Any() — different Dcol elements may satisfy different conditions.
Dcol.Any(d => d.Name == "A1B1C1Dcol1") && Dcol.Any(d => d.Enum == Enum1)
// No child FilterSet → any-object scope
Filters = [
    new Filter { PropertyPath = "B.C.Dcol.Name", Operation = "eq", TestValue = "A1B1C1Dcol1" },
    new Filter { PropertyPath = "B.C.Dcol.Enum", Operation = "eq", TestValue = "Enum1" }
]
HasCount(1) — Dcol[0] has Name; Dcol[0] also has Enum1 → match
Same-object scope — sscMatchSame1 / sscMatch2
Child FilterSet on the Dcol filter wraps both conditions in a single Any(). The SAME Dcol element must satisfy both Name and Enum. Dcol[0] satisfies both, so A1 still matches.
Dcol.Any(d => d.Name == "A1B1C1Dcol1" && d.Enum == Enum1)
// Child FilterSet → same-object scope
new Filter {
    PropertyPath = "B.C.Dcol",
    FilterSet = new FilterSet {
        Operator = Operator.AND,
        Filters = [
            new Filter { PropertyPath = "Name", Operation = "eq", TestValue = "A1B1C1Dcol1" },
            new Filter { PropertyPath = "Enum", Operation = "eq", TestValue = "Enum1" }
        ]
    }
}
HasCount(1) — same result here; difference emerges in Pair 2

Pair 2 — D.Ecol: conditions that can't be satisfied by one element

Ecol[0] has Name="A1B1C1D1Ecol1" and Enum=Enum1. Ecol[1] has Enum=Enum2. Asking for Name=Ecol1 AND Enum=Enum2 — no single element has both.

Same-object scope — Ecol_SameObjectScope_NoMatch
No single Ecol item has Name="A1B1C1D1Ecol1" AND Enum=Enum2. The single Any() returns false.
Ecol.Any(e => e.Name == "A1B1C1D1Ecol1" && e.Enum == Enum2)
new Filter {
    PropertyPath = "B.C.D.Ecol",
    FilterSet = new FilterSet {
        Operator = Operator.AND,
        Filters = [
            new Filter { PropertyPath = "Name", Operation = "eq", TestValue = "A1B1C1D1Ecol1" },
            new Filter { PropertyPath = "Enum", Operation = "eq", TestValue = "Enum2" }
        ]
    }
}
HasCount(0) — no single Ecol item satisfies both conditions
Any-object scope — Ecol_AnyObjectScope_Matches
Ecol[0] satisfies the Name filter; Ecol[1] satisfies Enum=Enum2. Independent Any() chains — different items, both true under AND.
Ecol.Any(e => e.Name == "A1B1C1D1Ecol1") && Ecol.Any(e => e.Enum == Enum2)
// No child FilterSet → any-object scope
Filters = [
    new Filter { PropertyPath = "B.C.D.Ecol.Name", Operation = "eq", TestValue = "A1B1C1D1Ecol1" },
    new Filter { PropertyPath = "B.C.D.Ecol.Enum", Operation = "eq", TestValue = "Enum2" }
]
HasCount(1) — Ecol[0] and Ecol[1] together satisfy both filters

Pair 3 — Bcol multi-level: conditions that belong to different Bcol items

Bcol[0] (A1Bcol1) has C.Value=123. Bcol[1] (A1Bcol2) has C.Value=22. Asking for Name=A1Bcol1 AND C.Value=22.

Same-object scope — MultiLevel_BAndC_SameScope_NoMatch
The same B instance must satisfy both B-level (Name) and C-level (C.Value) conditions. A1Bcol1 has the Name but C.Value=123, not 22. No match.
Bcol.Any(b => b.Name=="A1Bcol1" && b.C.Value==22)
new Filter {
    PropertyPath = "Bcol",
    FilterSet = new FilterSet { Operator = Operator.AND, Filters = [
        new Filter { PropertyPath = "Name",    Operation = "eq", TestValue = "A1Bcol1" },
        new Filter { PropertyPath = "C.Value", Operation = "eq", TestValue = 22 }
    ]}
}
HasCount(0) — no single Bcol item has both Name=A1Bcol1 AND C.Value=22
Any-object scope — MultiLevel_BAndC_AnyScope_Matches
Bcol[0] satisfies Name=A1Bcol1; Bcol[1] satisfies C.Value=22. Different items, independent Any() traversals — A1 matches.
Bcol.Any(b => b.Name=="A1Bcol1") && Bcol.Any(b => b.C.Value==22)
// No child FilterSet → any-object scope
Filters = [
    new Filter { PropertyPath = "Bcol.Name",    Operation = "eq", TestValue = "A1Bcol1" },
    new Filter { PropertyPath = "Bcol.C.Value", Operation = "eq", TestValue = 22 }
]
HasCount(1) — Bcol[0] satisfies Name; Bcol[1] satisfies C.Value

Nested scopes — C-S-C-S hierarchy

cscsMatchSame Four-level same-object scope: Bcol → C → Dcol → E with correlated scoping at every collection boundary.
The specific Bcol item, its C.Dcol item, and the E under that Dcol item must all jointly satisfy their conditions. The name describes the pattern: Collection → Scalar → Collection → Scalar.
Bcol.Any(b => b.Name=="A1Bcol1" && b.C.Dcol.Any(d => d.E.Name==p1 && d.E.Value>p2))
new Filter { PropertyPath = "Bcol", FilterSet = new FilterSet {
    Filters = [
        new Filter { PropertyPath = "Name", Operation = "eq", TestValue = "A1Bcol1" },
        new Filter { PropertyPath = "C.Dcol", FilterSet = new FilterSet {
            Filters = [
                new Filter { PropertyPath = "E", FilterSet = new FilterSet {
                    Operator = Operator.AND,
                    Filters = [
                        new Filter { PropertyPath = "Name",  Operation = "eq", FilterType = FilterType.TestValueParam, ParamKey = "param1" },
                        new Filter { PropertyPath = "Value", Operation = "gt", FilterType = FilterType.TestValueParam, ParamKey = "param2" }
                    ]
                }}
            ]
        }}
    ]
}}
HasCount(1, match) — A1 matches when param1 matches an E.Name and param2 < E.Value

CORE Null Safety 3 tests

NullCollection_NullGuardReturnsFalse A collection navigation property that is null evaluates to false, not a NullReferenceException.
A2.Bcol is null. The auto-injected null-guard wraps the Any() call in a null-check. A2 evaluates to false safely; A1 (with Bcol populated) is the only match.
new Filter
{
    PropertyPath = "Bcol",
    FilterSet = new FilterSet {
        Filters = [ new Filter { PropertyPath = "Name", Operation = "eq", TestValue = "A1Bcol1" } ]
    }
}
HasCount(1) — A1 matches; IsFalse(func(A2)) — null Bcol returns false, no throw
NullChecksDisabled_SkipsNullGuard enableNullChecks: false suppresses null-guard injection entirely.
Useful when the caller guarantees non-null navigation or the LINQ provider handles nulls natively in its translation. The expression is simpler but callers assume responsibility for null data.
Expression<Func<A, bool>> expr = FilterBuilder<A>.ProcessFilterSet(filterset, enableNullChecks: false);
HasCount(1) — flat data still matches correctly when no nulls are present
NullFilterSet_NoFilters_ReturnsAll A FilterSet with neither Filters nor FilterSets produces a match-everything predicate.
The degenerate empty case compiles to Expression.Constant(true) — all items pass through without throwing. Same behavior as BranchIfNoMatch = null and SwitchDefault = null.
var filterset = new FilterSet { Operator = Operator.AND };
// Filters = null, FilterSets = null — compiles to Expression.Constant(true)
HasCount(_data.Count, match) — all items returned

OPS IsNull / IsNotNull 6 tests

IsNull_MatchesNullProperty  ·  IsNotNull_MatchesNonNullProperty A2.B.Name is null; A1.B.Name is "A1B1".

RHS JSONPath + Math Transform (TestValueJson + TestValueExpression) 1 test

cscsMatchAnyParamJsonExpr Three-stage RHS pipeline: JSONPath extraction → math transform → constant baked into expression.
